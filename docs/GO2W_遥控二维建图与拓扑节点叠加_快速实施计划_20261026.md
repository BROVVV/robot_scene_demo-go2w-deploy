## 1. 目标与最终使用方式

用户用 Unitree 实体遥控器驾驶机器狗时，同步完成：

1. 激光与里程计持续构建二维占据栅格地图。
2. 相机持续识别、三档分类和建立对象拓扑。
3. 拓扑中具有有效地图坐标的第一、第二档节点，显示在二维地图的真实物理位置。
4. 危险节点在蜘蛛网拓扑和二维地图中同时标红，复用同一告警事件。
5. 两个视图使用同一物体 ID：点选拓扑节点可以定位到二维地图，点选地图节点可以查看同一物体详情。

用户不需要开启自主搜索，也不需要下发导航目标。二维建图依赖 SLAM 和定位数据，不依赖自主运动执行。

蜘蛛网图保留适合阅读关系的自由布局；二维地图中的节点必须使用真实坐标。不能把蜘蛛网布局坐标缩放后贴到地图上。

### 2.3 本次应修的明确缺口

1. **遥控启动器仍以 plain_slam 为主。** `start_remote_control_mapping.sh` 检查和启动的是三维建图及其快照写入器，没有把独立二维建图接入同一入口。
2. **遥控物体定位仍使用 `PlainSlamSpatialProvider`。** 当前构造固定订阅 `/go2w/slam/map_2d` 和 `/go2w/slam/odom_base`，产生 `pslam_map` 物体；它不是当前二维 `/map` 的 `map` 坐标。
3. **二维地图只是借用三维点云显示。** `nav2_web_map_bridge.py` 只提取占用值大于等于 50 的栅格作为点，丢失自由区和未知区的完整显示数据。
4. **前端仍有三维投影。** `slam_map_3d.js` 对物体使用 z 高度和倾斜视角，不能作为严格的二维地图落点显示；普通点标记也使用红色，会与危险标记冲突。
5. **拓扑与地图可见对象集合不一致。** 地图显示门又执行一次不同置信度过滤，导致已有有效拓扑节点消失。
6. **地图身份不统一。** 当前二维显示桥通过 `SlamWebMapState` 生成自身 epoch，`Nav2SpatialProvider` 又读取关键帧图的 map_id/epoch。接通后必须统一来源，不能让展示进程重启等于新建地图。
7. **遥控入口尚未完整接入关键帧锚定。** 当前主要在检测到 map→odom 跳变时调用通用重投影；二维 SLAM 回环需要按关键帧图修正历史物体，不能仅靠一次全局刚性平移。

结论：现有“地图叠加物体”基础可用，当前遥控模式也确实在工作；但“实体遥控时同时建二维地图，并将同一拓扑节点准确贴上去”还需要本计划的接线与显示修正。

## 3. 最简改造架构

```text
实体遥控器 → 机器狗运动
                  │
       ┌──────────┴───────────┐
       │                      │
激光 + 轮式里程计          RGB-D 相机
       │                      │
独立二维 SLAM             识别、分类、跟踪
       │                      │
 /map + TF + 关键帧图 ──→ 采集时刻的物体定位
       │                      │
二维地图显示快照          同一份 SemanticObjectMap
       │                      ├→ 蜘蛛网拓扑
       └───────────────┬──────┘
                       ↓
            二维地图 + 同 ID 物体节点 + 危险标记
```

默认让本轮遥控建图使用二维 `map` 作为语义物体坐标。已有三维地图可保留为独立可选视图，不要求本轮把两套地图做跨系统融合。

不要同时维护一份“二维识别物体”与一份“拓扑识别物体”；只是同一实体数据的两种显示。

## 6. 修改三：统一地图身份，接入回环后的物体重投影

### 6.1 统一身份

二维模式下，以现有关键帧图的 `map_id`、`map_epoch` 作为当前建图身份来源。二维显示桥订阅同一关键帧图，并将标识写入地图快照和元数据。

物体、拓扑与栅格显示快照全部使用同一 `frame_id=map` 和 epoch；不要从显示桥随机生成的新 epoch 给旧物体重新盖章。

- `/map` 正常扩展或 origin 改变不代表新地图，不清空物体。
- 网页或显示桥重启不代表新地图，不清空物体。
- SLAM 重置并建立新坐标系时才开始新 epoch，旧节点不混入。
- 关键帧身份暂未到达时，地图底图可以先显示，物体叠加显示“等待地图关联”，不伪造配对成功。

保留现有 `frame_id + map_epoch` 叠加检查，修正数据来源而不是删除检查。地图身份和位置正确是落图所需逻辑，不扩展成新的版本管理系统。

### 6.2 复用已有锚点能力

当前代码已有：

- `Nav2SpatialProvider.anchor_map_point()`
- `Nav2SpatialProvider.reproject_anchor_point()`
- `SemanticObjectMap.reproject_observations()`
- 自主搜索入口中的关键帧观测接线，可针对性复用。

每次有效物体观测保存原相机坐标、采集时间和锚点信息，包括关键帧 ID、局部坐标、map_id/epoch。关键帧图 revision 改变且锚点位姿发生修正时，用现有方法重新计算物体地图坐标，同步更新地图标记和距离关系。

不要只检查机器人当前位置是否跳变，也不要等相机再次看到旧物体才修正。SLAM 回环可能局部改变历史轨迹，旧物体应跟随所属关键帧移动。

这一步优先补接现有函数，不开发新的图优化算法。

## 7. 修改四：二维地图与拓扑使用同一有效节点集合

主要位置：

- `app/spatial/semantic_object_gate.py`
- `app/spatial/object_display_snapshot.py`
- `remote_control_semantic_mapping_worker.py` 的对象与拓扑发布部分。

默认规则：**当前有效拓扑节点中，具有可信的本图坐标者，都应有对应二维标记。**

实现时由同一轮物体更新同时投影出拓扑与地图对象：

- `node_id` 与 `object_id` 使用同一个稳定 ID。
- 共同要求第一或第二档、`topology_eligible=true`、有效位置及正确的地图身份。
- 已被拓扑接纳的节点不再因旧“三维包围盒显示阈值”而悄悄消失。节点入图质量标准只在共同入口应用一次。
- 可以保留灰色或淡色的待确认/陈旧样式，但两个视图对有效性与状态的解释一致。
- 确实缺少位置的拓扑节点保留在关系视图，详情明确写“未定位”，不在二维地图随便安排一个位置。
- 第三档退出拓扑时，二维标记也退出；同一 revision 下不能一个视图已删、另一个仍在。
- 危险标签、档次和最近观测字段贯通，两边共享一条告警，不各自生成事件。

不要为“数目相同”直接降低所有物体置信度要求或把背景碎片放进图。需要统一的是已接纳节点的投影规则。

### 8.2 前端二维分支

### 8.3 坐标换算必须一次写对

对于物体 map 坐标 `(x, y)`，栅格 origin 为 `(ox, oy, θ)`、分辨率为 `r`：

```text
dx = x - ox
dy = y - oy
local_x =  cos(θ) * dx + sin(θ) * dy
local_y = -sin(θ) * dx + cos(θ) * dy
cell_x = floor(local_x / r)
cell_y = floor(local_y / r)
图像格行号 = height - 1 - cell_y
```

绘制节点用连续坐标而非整数格中心，并与底图使用同一缩放、平移及 y 轴翻转。支持非零 origin、旋转 origin 和地图扩展，不能只在原点为零时看起来正确。

语义节点可以落在障碍格上，例如柜子或树本身就是障碍；不能为了显示把它吸附到附近自由格。目标中心超出当前二维栅格时，标为超出地图范围，不裁到边缘伪造位置，可在视口边距显示原坐标标记。

## 9. 两个视图联动与简单保存

### 9.1 节点联动

- 点击二维标记：显示同一对象详情，并高亮蜘蛛网节点。

- 不把两个视图分别生成的数组下标当作 ID。

### 9.2 保存当前结果

第一版复用已有地图保存能力，将同一次会话的内容放在同一目录：

```text
map.yaml + map.pgm
现有 SLAM posegraph/data（保存工具已支持时沿用）
semantic_objects.json
semantic_topology.json
hazard_events.json 或已有事件记录
简短的地图身份与生成时间元数据
```

占据地图与语义节点分别保存，节点不烧进 PGM 障碍像素，否则后续地图会被文字和符号污染。

不做复杂归档平台。保存时捕获一致的语义/拓扑 revision；PGM 保存前后地图若已变化，明确记录来源时间，不声称跨文件天然是同一瞬间的原子快照。

本轮必需的是能保存和静态查看本次结果。重启后继续增量建图、跨天地图合并和自动重定位不作为本轮范围；将来加载旧地图进行在线叠加时仍需真实重定位，不能沿用上次机器人位置。

## 11. 最少验证与交付要求

沿用用户的效率要求，不安排全量测试和多轮验收。完成后集中做以下三项即可：

1. **语法与一次离线投影检查。** 对修改文件做基础检查，用一张非零且旋转 origin 的小栅格验证一个已知点；同时确认未知/自由/占用颜色、地图尺寸变化和有效空占用图可显示。无需新建测试平台。
2. **只读运行检查。** 确认二维建图、拓扑和物体叠加均来自同一 map/epoch；对同一 revision 比较有效定位节点 ID 集合，确认危险节点颜色字段一致。只看“接口返回 OK”不足以证明节点已显示。
3. **一次短遥控演示。** 用户遥控直行并转弯、经过普通物体和实验纸箱，再回看起点附近。观察二维地图扩展、同物体位置稳定、第三档不落图、危险标红。如发生回环，检查历史物体是否随底图修正；未触发回环则如实标注尚未现场验证。

现场演示由用户操作实体遥控器，执行 AI 不主动发送运动指令。没有现场条件时，完成代码和所有可独立完成的检查，再明确说明缺少移动演示，不能编造真机通过。

代码完成标准：

- [ ] 一个遥控启动入口同时提供二维建图、三档拓扑和节点叠加。
- [ ] 不依赖自主搜索或软件运动控制。
- [ ] 物体实际使用 map 坐标，不改标签冒充坐标变换。
- [ ] 图像采集时刻的位姿被用于定位。
- [ ] 同一有效拓扑物体在二维图上具有同 ID 标记；无法定位时有明确原因。
- [ ] 底图完整呈现自由、占用和未知，物体 z 不引起二维横向偏移。
- [ ] 回环重投影接线完成；地图扩展或网页重启不错误清空对象。
- [ ] 第三档移除、危险标红和节点选择在两个视图一致。
- [ ] 能保存二维地图及对应语义/拓扑文件。

最终交付只需说明关键改动、准确启动命令与 URL、少量检查结果和未现场验证项。不要把“已有接口”“有物体 JSON”或“能显示障碍点”写成完整二维语义建图已通过。
