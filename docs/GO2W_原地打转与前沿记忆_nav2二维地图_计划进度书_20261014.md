## 2. 已经做了什么

### 2.1 问题一：把「原地打转」变成可判

原来喂给卡死判据的 `repeated_heading_count` 是
`graph.sector_visited_count(heading_sector)`，它在**一个 Place 内部只返回 0 或 1**，
而阈值 `repeated_heading_limit = 3` —— 这个分支**数学上不可达**。同时
`_last_execution_moved = bool(result.succeeded)`，只要后端报成功就把无信息计数清零。

改动（`app/live_robot/autonomous_explorer.py`，行号会漂，以符号名为准）：

| 符号 | 改成了什么 |
|---|---|
| `_in_place_turn_streak` 计数（`_update_memory` 内） | 数"上一轮是原地转向 **且** 这一轮没换到任何新信息"的连续轮数 |
| `_stuck_state` 里的 `repeated_heading_count` | 喂上面那个真实计数 |
| `_did_translate` | 失败一律算没动；有位移遥测以遥测为准；无遥测再看命令本身要不要平移 |
| `_observed_translation_m` / `_MIN_OBSERVED_TRANSLATION_M` | 新增：从 `observed_motion` 读位移，读不到返回 `None`（= 没有证据，不是 0） |

### 2.2 问题二：接上 `mark_frontier_visited`

`_settle_frontier_selection` 成为唯一写入口，判据全部要求**正向证据**（拿不到就不写）：
到达半径内 ⇒ visit；连续 3 次规划后一点没挪 ⇒ fail；有位移但没到 ⇒ 什么都不写。
下游把黑名单当**扣分**而不是**过滤**——这是刻意的：拉黑若做成过滤，
`reachable_frontier_count` 会掉到 0，把"卡住"伪装成"穷尽"。

### 2.3 对抗审计抓出的三个 HIGH（全在我自己刚落的代码里）

落地的形状（`app/live_robot/autonomous_explorer.py`）：

- **闸门**：`spin_condition = (not self.dry_run) and self._in_place_turn_streak >= repeated_heading_limit`
- **干跑豁免**：干跑的命令按构造全是转向、又没有真观测 ⇒ 合成流会让链路自检冒出 `stuck_detected` 与脱困动作（既有负控 `test_dry_run_never_self_reports_as_stuck` 钉的正是这条）

### 2.4 三条 HIGH 的修法与新增的折算器

| 新增/改动 | 作用 |
|---|---|
| `_commanded_translation_m(goal, pose)` | 两种后端都认：先看 `relative_dx/dy`，否则用 `hypot(goal.position - pose)` |
| `_commanded_turn_deg(goal, pose)` | 两种单位都认：`goal.yaw` 是**度**、`RobotPose.yaw` 是**弧度**，并回绕到 ±180 |
| `_MIN_COMMANDED_TRANSLATION_M = 0.02` | 顶掉 `== 0.0`。取 2 cm 的理由写进代码注释：真机最小步幅约 0.10 m，差一个数量级 |
| `_classify_no_information` 的 `open_frontiers` | 改用 `.get("status") or .get("state")` |
| 主循环 | **只取一次** `command_pose`，同时喂 `_did_translate` 与 `_record_execution_history`（两次采样不一致正是残差来源） |

### 2.4-2 第二轮审计之后补的两处（都在默认路径上）

| 改动 | 为什么 |
|---|---|

### 3.4 它治不治「瞎转」：**结论——既不必要也不充分，而且因果是反的**

v1 里这条写的是"待验判断"。**追查跑完，三个对抗镜头（可达性 / 反例 / 必要性）全部驳倒了"修好二维图就能避免瞎转"这条因果，`notRefuted: 0`。** 四条硬事实：

1. **产出"原地转"的分支根本不读二维栅格，而且是短路优先。** `LOCAL_SCAN` 在**前沿抽取之前**就 `return`（`run_semantic_exploration.py:3332-3420`，3420 已返回，3432 才做 frontier 抽取），它的入参只有 `heading_coverage` / `_place_scan_has_new_info` / `LocalScanState` 配额 / 当前 yaw / 当前 pose；`STRONG→VERIFY` 走 `_select_verify`，只读 `semantic_map.objects` 里置信度最高者的 bearing/confidence（`long_term_goal_selector.py:352-384`）。栅格的**唯一**两个消费点是前沿分支的候选打分与 `backend=nav2` 时的执行闸门。
2. **最近的真机会话 0 次走到前沿分支。** 跨全部 `outputs/live_runs` 统计 `selected_goal` 的来源：`local_scan 563` / `local_goal_executor 210` / `unvisited_sector 50` / `semantic_anchor 43`；长期意图 `EXPLORE_FRONTIER 38` / `APPROACH_TARGET 16`。2026-10-08 与 10-14 的会话只选了 `local_goal_executor` 与 `local_scan`。
3. **「转」的时候图是健康的。** 三条真机运动会话（17:46 / 18:08 / 18:14）跑的时候 `map_diag` 是 `HEALTHY`、revision 在涨、位姿正常，且 `unique_places=1`（一直在 P1：`ROTATE_VIEW -15° → RELATIVE_MOVE +0.1 m → ROTATE_VIEW +30°`）。地图直到 **20:33** 才冻结。
4. **冻结的因果是反的**：不是"图坏了导致瞎转"，而是**原地转向 → LIO 发散 → 图冻结**（`episode 9/10/11`：轮式 `dxy=0.000/0.024/0.022 m`，LIO 却产生 `17.19/521.47/1099.44 m` 假平移）。冻结后 Nav2 才刷 `Robot is out of bounds of the costmap!`。

  也就是说"哪些方向我已经探过"今天既不来自二维栅格，也不来自拓扑前沿自己的状态位。
- 「瞎转」的两个结构性成因（无信息计数被每轮清零、`repeated_heading_count` 数学不可达）
  与地图无关，今天已经修在决策层。

**⇒ 对优先级的影响**：`configs/go2w/navigation_gate.yaml` 一类闸门不在这条链上（**别把它当治瞎转的手段**）；要治瞎转，杠杆在 §3.3 清单乙（item6/7/8），不在二维图新鲜度。这一条已写进 §5-2-2 让你定优先级。
