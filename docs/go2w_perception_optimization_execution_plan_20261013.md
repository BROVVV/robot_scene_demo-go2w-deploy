### 2.2 当前流程与已经具备的能力

```text
网页请求（默认 grounded_sam；CLI 默认值与之不同）
  → 抓取 RGB-D、记录源帧与位姿
  → RAM++ 生成/缓存场景词
  → 目标词 + 锚点词 + 场景词

  → 过滤 / NMS → SAM2 图像分割 → mask RLE
  → 深度定位 / 语义实体 / 关系 / 地图
  → 候选匹配 → 按条件调用 VLM Verify
  → 规划 / 执行 / 等待 → 下一轮观察
```

已实现：会话内常驻 worker、SAM2 tiny、mask 分数门槛、单帧多框分割、RAM 限频、检测锁和同帧结果缓存。不得把这些重新包装成新增优化。

尚未实现或存在缺口：DINO 同帧逐词复用 backbone；高效等价 RLE；目标与普通场景候选明确分离；主入口完整 TargetProfile 接线；跨帧跟踪；移动期间独立运行的观察与决策。

当前主机为 RTX 3070 Laptop 8GB；当时目标为“绿色垃圾桶”，7 个目标词 + 12 个 RAM 场景词，静止同场景 3 帧。

## 4. 阶段一：现有实现的等价优化

**目标：**保持模型、词表、阈值、候选语义与外部输出契约不变，消除同帧重复 backbone 和 Python 像素扫描。用户说“先做第一阶段”，即完成本节全部必做项。

### 4.1 必做任务

1. **固化基线与可重跑入口。**复用已有隔离实验，整理为不会覆盖旧证据的离线回放工具；同时测生产子进程路径。对照必须使用相同图像、词表、权重、阈值和精度。现有 `scripts/benchmark_grounded_sam.py` 可参考，但仅重复 `detect()` 不足以覆盖 RAM 与完整链路；其模型加载次数由进程数推算，也不能替代真实加载事件。
2. **同帧 DINO 特征复用。**围绕 `_predict_all_prompts()` 及底层模型缓存生命周期实现帧级上下文。在同一个预处理图像的多个词之间保留特征；不缓存依赖文本的后续结果。帧结束、异常、目标更换和 worker 退出时清理；跨帧和不同预处理尺寸不能错误复用。同帧高召回重试是否复用须明确且有测试。
3. **等价向量化 RLE。**替换 `_encode_mask_runs()` 的逐像素循环，保持 `[row, start, length]`、行顺序、零基坐标、长度及 JSON 类型不变。用旧实现作对照，验证空/满 mask、单像素、首尾边界、非连续数组、多连通区域和随机 mask；解码后逐像素一致。
4. **生产路径接入与回退。**实现局部、可关闭的优化选项，保证网页和 CLI 到 worker 的实际值可查。不能只把 monkeypatch 留在实验脚本。默认启用新路径的前提是等价性与性能验收通过；保留旧实现用于对照和回退。
5. **补齐必要可观测性。**记录 `detector_backend`、请求/帧 ID、词数、前向次数、backbone 次数和分项耗时。本地检测不能增加云端 API 计数；兼容已有日志读取方，必要时保留旧字段并标明含义。GPU 同步计时只在 profiling 模式打开。

### 4.2 本阶段明确不做

不减少场景词，不改检测阈值，不引入多词合并，不修改候选筛选，不更换模型，不引入跟踪，不改导航节奏。不把 FP16、量化、TensorRT 或降分辨率纳入“等价”优化。

提前初始化现有 worker 属于本阶段完成后的可选体验改进，**不计入热态提速，也不是本阶段完成的前提**。若另行实施，应单独记录从用户启动到 ready/首结果的总时间，不能只是把等待隐藏到启动界面之前。

### 4.3 验收标准

- [ ] 同帧多个词只进行必要的一次 backbone 编码；新帧重新编码；异常后下一帧仍正确。
- [ ] 新旧路径在固定输入上对象顺序、标签、分数、bbox、mask RLE 一致。相同运行环境优先完整 JSON/hash 对照；若原始模型自身非确定，先量化原版重复运行差异，不能擅自扩大容差掩盖变更。
- [ ] 常驻 worker 没有变成每帧新建，也没有并发污染缓存或显存持续增长。
- [ ] 真实生产 IPC 路径也获得提速；不仅独立函数变快。
- [ ] 定向回归、真实回放、开关关闭后的旧路径验证完成；全部原始记录可复查。

实测参考是 4.47 → 3.22 s，可把约 20%～30% 热态改善作为本场景的初始目标，不作为对所有场景的保证。没有复现收益时先查计时、词数、GPU 状态与代码接线，再报告原因。

现有测试入口包括：`tests/test_grounded_sam_runtime.py`、`tests/test_grounded_sam_persistent_worker.py`、`tests/test_grounded_sam_prompt_integration.py`、`tests/test_sam2_min_box_score.py`。按需要新增缓存生命周期和 RLE 等价测试；既有部分测试依赖历史数据，应单独说明跳过或基线失败。

**阶段结束应得到：**原有识别链路语义不变、生产实现可用、热态更快；仍然可能每次检测要数秒，尚不承诺边走边决策。

## 5. 阶段二：检测分频、候选分离与复核调度

**前提：**阶段一的实现、对照入口和输出契约可用。**目标：**减少重复全场景检测和无关复核，保留 GroundingDINO/SAM2。

### 5.1 必做任务，按以下顺序实施

1. **修正主入口 TargetProfile 接线。**让 controller 使用的目标画像、类别别名、属性与关系锚点实际到达 detector。检查任务切换时缓存失效；不要误接另一个同名 TargetProfile 类，也不要为每帧重新调用 LLM 解析任务。
2. **区分结果职责。**明确 `scene_objects`、`target_candidates`、`relation_anchors`，使用共同实体/检测 ID 关联，允许同一对象承担多个角色。`target_present` 必须基于目标候选的三态证据，不再等价于“检出了任意物体”。普通场景对象仍进入地图；不能因此删掉场景理解。
3. **修正 Verify 候选选择。**仅在目标候选中排序，并保留不确定属性对应的 POSSIBLE。验证“高分椅子 + 低分目标桶”不会被椅子抢占复核；不要简单用颜色字符串严格过滤所有潜在目标。
4. **分频检测。**每次目标刷新处理目标及必要锚点，普通场景按间隔、明显视角变化、场所切换和缓存过期触发全量刷新。设计可配置频率和每类结果的时间戳/有效期，记录场景刷新最大等待，避免目标任务让地图更新永久饥饿。RAM 类别缓存和 DINO 检测调度是两件事，要分别控制。
5. **有界异步 Verify。**沿现有 daemon 接口提交复核，搜索线程不再同步阻塞几十秒；待复核保持 POSSIBLE，不能据此宣布成功。限制在途请求与最新待处理请求，绑定 task/frame/candidate ID；阶段三有 track 后扩展为 track+generation。超时输出 UNKNOWN/TIMEOUT，不做负例；不重复启用备用子进程。若服务不能取消运行中请求，保留在途状态直到终结/确认失效，不能在客户端超时后无限提交。增加限频、失效结果丢弃和队列观测。
6. **评估多词分组前向。**实现可关闭的实验分支，使用明确的 token span/positive map 把输出关联回每个词，处理别名与重复框。禁止只把词拼成一个字符串后按整段 phrase 赋类。与逐词路径比较召回、串词、重复框、分数变化和延迟；若质量门槛不通过，默认仍使用逐词模式，但分频与候选修复必须独立落地。

多词分组不是等价优化。它的必交付是可复现对照与明确采用/拒绝结论，而非无条件替换默认路径。阶段二整体仍必须通过分频或复核调度获得实测收益。

### 5.2 验收标准

- [ ] 只有普通物体、没有目标候选时，不因最高场景分数触发目标复核。
- [ ] 目标低于背景分数、别名命中、属性不确定和关系锚点任务均有行为测试。
- [ ] 当前网页入口确实使用完整目标画像；更换目标后旧候选与旧复核不能串入新任务。
- [ ] 目标检测和场景刷新次数可分别统计；非目标对象仍能按规定周期进入地图。
- [ ] 用确定性故障注入验证慢响应、超时和乱序不会阻塞观察或产生假“找到”；真实 provider 的连通/延迟情况另列，不用 mock 冒充云端成功。
- [ ] 固定回放集通过通用质量门槛；报告每分钟 DINO 调用数、目标刷新延迟、场景刷新间隔、Verify 次数与触发原因。
- [ ] 多词分组给出启用或保留旧路径的证据；所有配置完成端到端接线与回退验证。

测试从 `tests/test_ram_scene_terms.py`、`tests/test_ram_target_priority.py`、`tests/test_grounded_sam_prompt_integration.py`、`tests/test_target_profile.py`、`tests/test_target_tri_state.py`、`tests/test_verify_fresh_frame_policy.py` 以及相关网页参数测试中选择受影响项，并补充上述错误案例。

**阶段结束应得到：**更少的无效检测/复核、更快的目标更新，结果职责清楚；尚未解决所有跨帧开销与导航阻塞。

## 6. 阶段三：跨帧跟踪与异步感知流水线

**前提：**阶段二的角色划分、刷新调度、候选身份与复核接口可用。**目标：**建立持续取帧、跟踪、重检测、语义更新各自运行的流水线，让感知不再依赖“一次动作结束才开始观察”。

### 6.1 必做任务

1. **建立不可混淆的帧包。**携带 frame_id、采集时间、主机接收时间、时间戳质量、RGB/depth 引用、内参、采集时位姿与坐标变换、task generation。检查位姿插值与时钟域；缺数据标记不可用。文件/缓冲区在消费者处理完前不能被覆盖。禁止拿旧 RGB、最新 depth 和当前 pose 拼三维对象。
2. **改造现有异步管理器。**前台获取快照而非等待重模型；按需重用 `AsyncSemanticObservationManager`，避免旁路创建另一套互相竞争的 worker。输入采用“一个在处理 + 一个最新待处理”的有界策略，覆盖旧 pending 并记录丢帧；任务结果按源帧和版本合并。
3. **选择并实现跨帧传播。**先建立轻量框跟踪基线，再与 SAM2 视频传播比较；当视频模型成本/显存不合适时，选择质量达标的轻量方案。若选轻量框跟踪，mask 仍按需重算，不能平移旧 mask 后伪装成当前分割。EfficientTAM 是可选对照，不要求再装所有模型。
4. **周期与事件重检测。**发现目标前仍周期运行目标检测以发现新对象；发现后跟踪并定期重检测。低置信度、遮挡/出画、剧烈运动、重定位、任务切换、track 冲突触发失效或重检测。跟踪不能提供新类别/颜色确认，检测与 Verify 的证据等级保持区分。
5. **保留来源与真实帧龄。**记录 detection_source_frame、tracking_update_frame、semantic_source_frame 及各自时间，不能因为完成时间较新就把旧语义标记为 fresh。修复主流程里无条件 `semantic_age_ms=0` 或用当前 pose 覆盖源 pose 的路径；设置可配置的感知过期策略。
6. **单一地图写入者。**跟踪/检测/复核通过事件或不可变结果进入同一合并入口。拒绝乱序覆盖、旧 generation 和不匹配坐标系；深度和世界坐标更新使用对应帧数据。低频场景语义不能覆盖更新的目标位置。
7. **与当前主入口接通。**网页实际路径能够启动/关闭流水线并读取最新有效观察；同步旧路径保留回退。此阶段只完成运动期间可运行的感知服务与接口，Nav2 的持续决策/目标交接放到阶段五。

### 6.2 推荐调度结构

```text
相机 → 最新帧缓冲 ─→ 跟踪 / 当前帧定位 ─────┐
                 └→ 有界重模型调度器        │
                     ├→ 目标与锚点检测      ├→ 单一状态合并入口 → 最新有效观察
                     └→ 低频场景刷新        │
目标候选 → 有界异步 Verify ─────────────────┘

独立的导航/避障控制消费有效观察，不等待云端回答。
同一 GPU 的重模型默认串行调度；线程并发不等于 GPU 耗时自动降低。
```

架构上允许相机、CPU 编码、网络复核、GPU 推理和控制重叠。暂不要求引入 ROS 分布式部署、消息中间件或多台计算机；先完成单主机内清楚的数据归属和背压，避免通信复杂度先于收益。

### 6.3 验收标准

- [ ] 连续序列包含目标进入、遮挡、重新出现、相似目标交叉与镜头运动；记录 ID 切换、恢复时间、新目标发现时间和定位误差。
- [ ] 插入慢检测/慢 Verify 后，采集与可用的跟踪路径仍继续；队列长度有上限，帧龄不随运行时间无限增长。
- [ ] 用不同帧的 RGB/depth/pose、结果乱序、任务切换和缓存文件复用做负向测试，均不会静默写入错误三维实体。
- [ ] 连续回放至少 10 分钟，线程/进程退出正常，显存和内存没有持续增长；记录各刷新频率、p95 帧龄与丢帧数。
- [ ] 与阶段二在同一序列比较：完整检测次数下降，同时通过质量门槛；目标更新的实际频率和帧龄改善。
- [ ] 网页配置 → 搜索 worker → 主流程 → 感知服务确实接通，关闭后可恢复旧同步行为。

可将“已发现目标的位置更新 5 Hz、主机接收后跟踪结果 p95 延迟低于 300 ms”作为首轮工程目标，**不等于语义识别或新目标发现达到 5 Hz**。最终报告必须拆开这三种频率，并说明哪项达标。若当前 GPU 调度不能达到，报告阻塞来源和当前上限，不填入目标值代替实测。

相关测试包括：`tests/test_async_semantic_observer.py`、`tests/test_semantic_freshness.py`、`tests/test_semantic_quick_absence_keeps_objects.py`、`tests/test_semantic_frame_object_observations.py`、`tests/test_semantic_entity_association.py`，并新增有界队列、跨帧一致性和跟踪恢复行为测试。

**阶段结束应得到：**持续感知与跨帧复用已接入，能够为边走边决策提供数据。**执行“前三阶段”到此结束，不得宣称已经完成连续走路。**

## 7. 阶段四：可选快速开放词汇检测器对照与接入

**目标：**在前述结构优化后，评估是否用 YOLO-World / YOLOE 替换 DINO 框检测。此阶段不是连续行走的必需前提，可以在阶段三之后继续做阶段五。

### 7.1 必做任务

1. 先在隔离环境对 YOLO-World、YOLOE 的可用权重、许可证、硬件需求和接口做核查，选更适合的一种完成端到端对照；另一种给出不选或延期的具体依据。不得同时无目的安装所有研究模型。
2. 建立统一框检测 adapter，保留标签映射、分数、坐标、候选角色和源帧契约；目标变化时更新文本提示缓存。默认保留现有 SAM2、depth 与实体关联。
3. 在相同输入尺寸/质量预算下与阶段三所用检测器比较；分别报告模型纯推理与完整链路。将文本提示初始化、词表更新、模型加载成本单列。
4. 对小目标、颜色属性、中文任务到英文别名、关系锚点和同类多实例做质量对照；若测试原生 mask，另测 mask 与三维定位质量，不能把框 AP 作为替代证据。
5. 通过配置接通完整网页路径，提供一键选择旧检测器的回退方式；达到质量/性能门槛才改默认。未通过时保留旧默认，并交付可重跑的拒绝结论。

### 7.2 验收标准

- [ ] 至少一个候选检测器有真实权重、真实图像的完整路径对照；不是只有论文 FPS 和独立 demo。
- [ ] 端到端延迟、目标候选召回、错误确认、mask/3D 质量、显存峰值均有数据。
- [ ] 更换目标、重新加载、模型缺失/OOM 的失败路径清晰，不静默返回“无目标”。
- [ ] 默认采用或拒绝替换的结论有证据。合法的“已验收”结果可以是“不替换”，但不得声称获得了并不存在的提速。

**阶段结束应得到：**一个基于本机与本任务数据的模型选择结论，以及可切换的检测器接入实现。

## 8. 阶段五：连续行走、持续观察与决策集成（独立扩展阶段）

**前提：**阶段三已验收；阶段四可选。**目标：**实现用户最终希望的“边走边取帧、边决策，减少无必要停走”。前三阶段不包含本节。

### 8.1 必做任务

1. 审查 `AutonomousExplorer` 的 execute/wait 路径与 `Nav2SearchBackend` 的在途目标处理。不能只把 `observe_while_moving` 改成 true；必须验证该配置真的传入并改变当前主入口行为。
2. 将感知更新、策略评估与 action 等待解耦，运动期间持续消费阶段三的观察；避免在 ROS 回调/控制线程执行模型推理或等待 Verify。
3. 设计明确的导航目标生命周期：active、pending、cancel_requested、terminal。根据 Nav2 action 的实际能力实现有序替换/取消确认或目标延续；禁止向仅支持单在途目标的接口不断提交并忽略 `GOAL_IN_FLIGHT`。
4. 增加路径进展、方向变化、目标距离与重规划最小间隔等滞回条件，避免每次新帧都撤销导航。复用已有局部规划/避障，不能让低频语义结果直接替代速度控制。
5. 明确感知过期、定位失效、障碍、导航失败、急停和用户停止的处理。地图仍允许安全前进时可继续当前有效目标；不确定是否安全时减速/停止，而不是为了连续行走取消保护。
6. 将“候选正在复核”“已确认并准备接近”“到达/搜索完成”分开。迟到的 Verify 不能让机器人追逐失效位置或直接宣布到达。
7. 先完成仿真/记录回放与状态机测试，再进行授权范围内的受监督低速真机实验。具体场地、速度、观察人员和停止方式写入实验记录，不能凭计划预设一个万能安全速度。

### 8.2 验收标准

- [ ] 运动期间确有新帧、有效感知更新和策略事件，不是重发同一缓存帧。
- [ ] 正常无障碍路线中，原先由同步检测/复核造成的停顿明显减少；对照总行程时间、停车时长、停车原因、有效行走占比、目标发现到动作更新延迟。
- [ ] 不通过禁止停止来提高连续性指标；避障、定位失效、急停、用户停止的行为符合现有约束。
- [ ] 在途目标交接无重复 goal、无取消风暴、无长期 `GOAL_IN_FLIGHT` 忽略、无旧结果覆盖新目标。
- [ ] 完成静态与动态验证的边界写清。没有真机运动授权或场地时，代码/仿真可完成，但本阶段真机最终验收仍待完成。

**阶段结束应得到：**在明确测试条件下，有实测证据支持连续搜索体验改善，而不是仅有“异步”架构图。

## 11. 论文对应关系与采用原则

| 论文 | 用于本计划的具体位置 | 不可直接推导的结论 |
| --- | --- | --- |
| [SAM 2，2024](https://arxiv.org/abs/2408.00714) | 阶段三：视频记忆与跨帧传播对照 | 当前 ImagePredictor 已自动具备视频跟踪 |
| [Efficient Track Anything，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/html/Xiong_Efficient_Track_Anything_ICCV_2025_paper.html) | 阶段三：视频传播成本不合适时的可选研究方向 | 本机 8GB GPU 上一定更快或一定可用 |
| [YOLO-World，CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Cheng_YOLO-World_Real-Time_Open-Vocabulary_Object_Detection_CVPR_2024_paper.html) | 阶段四：开放词汇检测与提示缓存 | 论文 FPS 等于机器人完整感知 FPS |
| [YOLOE，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/html/Wang_YOLOE_Real-Time_Seeing_Anything_ICCV_2025_paper.html) | 阶段四：提示重参数化、检测/分割替换对照 | 更高吞吐必然保持属性、关系和三维定位质量 |

阶段一的优先级来自本仓库的真实调用链和已完成隔离实验；阶段二来自重复逐词检测与候选职责混淆；阶段三、四再利用论文方法做有数据支撑的改造。最终选择以本项目的识别质量、端到端延迟和导航行为为依据。
