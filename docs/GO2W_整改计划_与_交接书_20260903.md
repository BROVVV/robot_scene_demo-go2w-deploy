## 5. 阶段二：修复 60°只执行30°

### 5.1 修改原则

保留单个物理 primitive 最大 30°的现有安全限制。一个逻辑 60°目标拆成两个 30°
primitive，并依据实际里程计闭环完成总角度；不要把安全上限直接改成 60°。

### 5.2 修改文件

```text
app/navigation/go2w_experimental_backend.py
app/navigation/models.py
app/live_robot/autonomous_explorer.py
scripts/go2w/run_semantic_exploration.py
app/manual_web_demo/static/search_ui.js
tests/test_go2w_experimental_backend.py
tests/test_local_scan.py
```

### 5.3 执行逻辑

在 `_execute_turn()` 中：

1. 保存逻辑请求 `requested_total_deg`；
2. 按 30°拆分，例如 `+60 → [l30, l30]`，`-60 → [r30, r30]`；
3. 每段执行前后读取 canonical `/go2w/odom/fused`；
4. 每段必须通过现有停止和角度验证；
5. 用累计实测 yaw 判断逻辑目标是否完成；
6. 第一段失败时禁止执行第二段；
7. 两段都完成后才返回逻辑 goal `SUCCEEDED`；
8. 若第一段实际转过头，第二段使用剩余角度，不能机械地再转满30°；
9. 最终误差超阈值时返回 `FAILED/ROTATION_NOT_CONFIRMED`，不能只根据 RPC success 成功。

建议事件字段：

```json
{
  "requested_total_deg": -60.0,
  "segment_count": 2,
  "segment_index": 2,
  "segment_step": "r30",
  "observed_total_deg": -57.4,
  "remaining_deg": -2.6
}
```

WebUI 显示“右转60°（2/2，已完成57.4°）”，不要把逻辑目标和单个 primitive 混为一条。

### 5.4 验收标准

- `±30°`：仍只执行一个 primitive；
- `±60°`：正常情况下执行两个 primitive；
- 实测累计角度与目标同号；
- 60°目标最终误差绝对值不大于 8°；
- 任一段失败后机器人停止，逻辑目标不成功；
- event 中同时保留逻辑请求、分段请求和累计实测角度。

## 6. 阶段三：修复搜索三四步后提前结束

### 6.1 修复确定的 Foxy logger 错误

文件：

```text
scripts/go2w/run_semantic_exploration.py
```

当前 ROS 2 Foxy logger 的 `warn()` 不接受 Python logging 风格的多个格式参数。把
2090 行附近改为单字符串，并统一使用 `warning()`：

```python
node.get_logger().warning(
    f"metric map not fresh; falling back "
    f"(provider={args.spatial_provider}, frontier count={len(frontiers)})"
)
```

同文件内其余 `warn()` 调用也检查一次，但只修改确实不兼容的调用，不做全项目机械重写。

### 6.2 修正异常分类

文件：

```text
app/live_robot/autonomous_explorer.py
app/live_robot/explorer_search_adapter.py
app/live_robot/search_state_store.py
```

当前逻辑是：

```text
candidate generator exception → candidates=[] → SEARCH_EXHAUSTED
```

修改为：

```text
candidate generator exception
→ 记录 PLANNING_ERROR/candidate_generator
→ 停稳
→ 允许一次新观测后的重新规划
→ 同一异常再次发生则 FAILED（不是 SEARCH_EXHAUSTED）
```

`SEARCH_EXHAUSTED` 只能表示真实搜索空间穷尽，不能表示 Python 异常、地图暂时不新鲜或
ROS 数据暂时缺失。

### 6.3 修正“空候选”的语义

空候选必须分三类：

| 情况 | 正确处理 |
|---|---|
| metric map stale/unavailable | `WAITING_FOR_MAP`，停稳并等待新地图后重规划 |
| 当前 Place 本地扫描配额耗尽，但有可达 frontier | 选择长期 frontier，继续移动 |
| 地图健康、全方向已扫描、所有可达 frontier 均已访问或失败 | 才允许 `SEARCH_EXHAUSTED` |

实现时复用已有 `frontier_extractor`、`spatial_reasoner`、`TopologyRoutePlanner`，不要增加第二套
候选系统。

### 6.4 local scan 配额规则

本次 `P1` 执行三次旋转后配额耗尽是正常的，错误在于长期目标分支随 logger 异常一起失败。
修复后要求：

- 配额只限制同一 Place 的原地扫描，不代表全局搜索结束；
- 真平移到新 Place 后有新的局部扫描配额；
- 配额耗尽时必须进入 frontier/route 分支；
- 没有健康地图时不允许盲当前进，应等待地图恢复并向 WebUI明确显示原因。

### 6.5 验收标准

- 重放本次会话不再出现 `warn() takes 2 positional arguments`；
- candidate generator 人工注入异常时结果为 `PLANNING_ERROR/FAILED`，不是
  `SEARCH_EXHAUSTED`；
- 有可达 frontier 时，三次 local scan 后第四次规划选择 frontier；
- 目标未找到且仍有可达区域时，搜索可持续超过 10 个 motion step；
- 只有满足真实穷尽条件时才输出 `SEARCH_EXHAUSTED`，事件里列出已扫描方向数、可达
  frontier 数、已访问数和不可达数。

## 8. 阶段五：先修 LIO 动态位姿，再谈三维地图显示

### 8.1 当前不能接受的状态

当前使用：

```text
LiDAR: Hesai PandarXT-16

IMU timestamp: receive-sensor offset aligner
Pandar↔base extrinsic: candidate_unconfirmed
```

禁止把它标记为正式标定通过。

### 8.2 采集最小动态标定数据

由用户用遥控器操控，执行 AI 只负责记录和监视，不下发自主运动：

1. 静止 60 秒；
2. 左转约30°，停5秒；
3. 再左转约30°，停5秒；
4. 右转约30°，停5秒；
5. 原地一周，低速完成；
6. 直行约1米，停5秒；
7. 原路退回或掉头返回起点。

必须同步记录：

```text
/hesai/pandarxt16/points_raw
/go2w/slam/pandar_points
/utlidar/imu
/go2w/slam/imu
/go2w/slam/imu_pose_raw
/go2w/slam/odom_base
/go2w/odom/fused
/go2w/slam/aligned_scan
/go2w/slam/map_3d
/tf
/tf_static
```

每个动作由用户口头或按键标记开始/停止时间，保存为一个 bag 和一份动作时间表。

### 8.3 先验证时间和轴向

新增或扩展只读分析脚本：

```text
scripts/go2w/analyze_lio_motion_alignment.py
```

脚本输出：

- `/utlidar/imu` 与 Pandar cloud 时间差的 median、p95、max；
- IMU `angular_velocity.{x,y,z}` 与 `/go2w/odom/fused` yaw rate 的相关系数；
- 最佳时间偏移及其置信区间；
- 左/右转时角速度符号是否与 fused odom 一致；
- 每个转向段的 wheel Δxy/Δyaw 与 pslam Δxy/Δyaw；
- 每段点云 scan-to-scan ICP 的旋转和平移残差。

判定顺序：

1. 若 IMU yaw 轴或符号错误，先修轴向变换；
2. 若角速度峰值时间错位，先修固定时间偏移；
3. 时间和轴向正确后，再求 Pandar↔IMU外参；
4. 最后才调整 LIO 匹配参数。

不要通过增大 correspondence distance 或降低健康阈值掩盖时间/外参错误。

### 8.4 修正 timestamp aligner

文件：

```text
ros2_ws/src/go2w_plain_slam_bridge/scripts/imu_timestamp_aligner.py
ros2_ws/src/go2w_plain_slam_bridge/scripts/imu_fallback_adapter.py
```

要求：

- 同一个 mapping session 使用经启动窗口估计并锁定的 sensor→ROS 时钟偏移；
- 运动期间不根据 callback 到达抖动持续拖动时间轴；
- 原始 sensor stamp、修正 stamp、offset 和模式进入诊断；
- 时间回退、重复或大跳变时停止给 LIO喂数据并要求重启 session；
- 不用“当前 callback 时间”直接覆盖传感器采样时间；
- Pandar point 内相对时间字段保持原值，deskew 使用同一时间语义。

### 8.5 修正 IMU轴向和外参

相关文件：

```text
configs/go2w/hesai_pandarxt16_extrinsics.yaml
scripts/go2w/generate_plain_slam_pandar_config.py
runtime/go2w/plain_slam/generated_lio_3d_params.yaml
```

执行要求：

- 根据动态 bag 求得 IMU→Pandar 的旋转和平移；
- 左右转都必须验证，不能只拟合单一方向；
- 直行段用于排除把转向误拟合成平移；
- 生成文件必须记录标定来源、bag路径、残差和配置哈希；
- `candidate_unconfirmed` 只有通过本计划动态门槛后才升级；
- 不手改 `runtime` 生成文件，修改源 YAML 后重新生成。

### 8.6 LIO 动态验收门槛

每个30°原地转向段：

```text
fused Δxy ≤ 0.10 m
pslam Δxy ≤ 0.20 m
pslam 与 fused yaw 同号
|pslam Δyaw - fused Δyaw| ≤ 5°
```

360°闭环：

```text
pslam position closure error ≤ 0.30 m
pslam yaw closure error ≤ 10°
同一墙面/桌面点云不得出现多份明显旋转副本
```

1米直行：

```text
pslam 与 fused 位移方向一致
位移长度误差 ≤ max(0.20 m, 20%)
结束 yaw 漂移 ≤ 5°
```

任一门槛不通过，不能进入 Web 三维地图最终验收。

## 9. 阶段六：改成真正的固定世界三维地图

### 9.1 只保留一个永久地图权威源

修改：

```text

scripts/go2w/plain_slam_web_cloud_relay.py

```

永久地图以 `/go2w/slam/map_3d` 的优化历史为权威，不再把每个
`/go2w/slam/aligned_scan` 不可逆地永久塞进同一个 voxel 容器。

建议契约：

```text
canonical map frame = pslam_map
authoritative permanent cloud = /go2w/slam/map_3d
latest scan = 仅实时预览或等待下一个 map keyframe
```

如果 `aligned_scan` 为 `pslam_odom`，而 `map_3d` 为 `pslam_map`：

- 没有时间戳对应的 `T_pslam_map_pslam_odom` 时，不混合两者；
- 有可靠变换时，latest scan 变换一次后只作为预览；
- 新 `map_3d` 到达时整体替换永久地图，使回环优化能纠正历史；
- 不通过修改 `header.frame_id` 假装完成坐标变换。

### 9.2 不再使用“静止后累积几帧”伪装连续建图

当前 Web 桥运动时丢弃全部 scan，停稳后再积累。这只能减少污染，不能形成真正随走随扩展
的地图。修改后：

- LIO/SLAM本身连续处理运动点云；
- Web永久地图跟随 `map_3d` keyframe更新；
- Web可显示 latest scan，但不得写入永久历史；
- UI明确显示“全局地图更新时间”和“当前scan时间”；
- 地图点数达到上限时使用体素降采样，不能按到达顺序删除整片旧区域。

### 9.3 分离“完整地图容量”和“WebUI显示点数”

当前实现的三个限制是：

```text
max_input_points = 8,000 / scan
max_accumulated_points = 40,000 voxels
max_web_points = 20,000 points / snapshot
voxel_size = 0.12 m
```

其中 `20,000` 是 WebUI快照的显示采样上限；更严重的是
`BoundedVoxelCloud` 只保留 `40,000` 个体素，超过后使用
`popitem(last=False)` 按时间删除最早加入的体素。机器人持续进入新区域后，旧房间会逐渐
从地图中消失。这种实现只能支持小范围预览，不能作为大范围三维地图。

修改后必须形成三个互相独立的容量层：

| 层 | 用途 | 容量规则 |
|---|---|---|
| SLAM权威地图 | 保存完整、可回环修正的世界地图 | 读取 `/go2w/slam/map_3d`，不受 Web点数上限影响 |
| Web桥全局缓存 | 对权威地图做体素化、生成快照 | 建议基线30万个全局体素，可配置20万～50万；超限时对全图重新均匀降采样 |
| 浏览器显示 | Three.js实时浏览 | 默认约5万个点，可配置到10万个；从整个地图均匀抽样，不只保留最新区域 |

具体要求：

1. 删除 `OrderedDict` 的“满了就删除最旧体素”策略；
2. 权威 `/go2w/slam/map_3d` 到达后，先在固定世界坐标中进行全局体素降采样；
3. 若全局缓存超过配置上限，对全部空间重新采样，保证地图边界内每个区域仍有代表点；
4. Web snapshot 从完整全局缓存做均匀空间采样，不能按插入顺序截断；
5. `max_web_points` 只控制浏览器传输和绘制负载，绝不能改变SLAM地图内容；
6. 默认将 `max_web_points` 从20,000调整到约50,000，真机测得浏览器性能不足时再降低，
   但降低后仍必须保持全地图空间覆盖；
7. Web传输频率与点数配套调整，避免用JSON以1.5Hz反复发送超大点集拖慢机器狗；地图
   没有新revision时不重复编码同一份点云；
8. UI同时显示“SLAM源点数、全局缓存体素数、Web显示点数和地图范围”，防止把
   `point_count=20000` 误解成完整地图只有两万个点。

建议快照新增字段：

```json
{
  "source_map_points": 486320,
  "global_cached_voxels": 286441,
  "web_display_points": 50000,
  "global_voxel_size_m": 0.12,
  "web_sampling": "global_spatial_uniform",
  "capacity_limited": false
}
```

不要为了追求点数保留无效噪声。大范围能力的判据是旧区域不丢、全局结构完整，而不是
单纯让浏览器渲染几十万重复点。

### 9.4 修正 reset 语义

当前 reset marker 只清 Web voxel，LIO已经发散时下一帧仍是坏世界坐标。新 session reset
必须同时做到：

1. 停止当前地图写入；
2. 清 Web snapshot；
3. 调用 LIO/SLAM reset service；如果上游没有 reset service，则有序重启 mapping launch；
4. 等待 IMU、LiDAR、odom和 map frame重新健康；
5. 新 session ID 到达后才开始显示新地图；
6. 旧 session 的迟到消息按 session/启动时间丢弃。

不需要建立复杂地图版本系统，一个单调 `mapping_session_id` 和启动时间即可。

- 行走到新区域后，起始区域仍保留在全局地图中；

- WebUI即使只显示约5万个采样点，也必须覆盖完整地图范围，不能只剩机器人附近区域；
- 典型浏览器上旋转、缩放地图保持可操作，不因盲目提高点数卡死页面。

### G.6 shell 陷阱（我踩过两次，别再踩）

- `pkill -f "xxx.py"` / `kill $(pgrep -f "xxx.py")` 会**匹配到自己的 bash 命令行**并把自己杀掉
  （表现为 exit code 144）。要么用括号技巧 `pgrep -f "xx[x].py"`，
  要么先 `ps` 拿到具体 PID 再单独 `kill <pid>`；
  **同一条命令里既 kill 又启动同名脚本一定会自杀**（启动那半截把明文路径带进了命令行）。
- `setsid cmd &` 拿到的 `$!` 不一定是最终进程的 PID（setsid 可能再 fork），

## I. 改代码前必须知道的契约（改坏会静默退化）

- **frame**：`aligned_scan`/`odom_base` → `pslam_odom`；`map_3d` → `pslam_map`（唯一权威永久地图）；

  漂移判定比较轮式与 LIO 的 (位移, 转角)，reason 是中文，会直接显示给操作员。
- **快照 key**：`mapping_session_id`（不是 `session_id`）、`source_map_points`、
  `global_cached_voxels`、`web_display_points`、`wheel_episode_delta_*`、`pslam_episode_delta_*`。
- **id 命名**：Place `P1/P2…`；frontier 节点 id `frontier:P{n}:{sector:02d}`，显示标签 `F01…`；
  对象 `obj_001…`；投影里**禁止**出现 `OBSERVED_FROM`/`FRONTIER_TO`/`MOVED_TO`。

## I2. 改代码前必须知道的契约（改坏会静默退化，不报错）

**frame → persistent 的精确映射链**（修复 3 依赖它，断哪一节都会让确认标记错位）：

```text
quick payload 的 id / frame_object_id
  → FrameObject.frame_object_id            (app/video/schemas.py:19-36，首字段)
  → FrameObject.to_dict()                  (asdict)
  → LiveObservation.scene_objects
  → _frame_object_id(item)
  → ObjectSpatialObservation.object_id
  → SemanticAssociation.source_object_id
  → persistent_object_id                   ← mark_target_confirmed 要的就是这个
```

**两条互斥的 VLM 通道**（这是 C2.1 根因的源头，别把它们合并）：
目标判定只走 `target_objects`；建图 / 拓扑只走 `scene_objects`（来自 `scene_objects_light`）。
`objects` 是兼容字段，**只含目标**，修复 1 没有改这个契约。

**quick → verify 两级确认**：quick 给 PRESENT / POSSIBLE / ABSENT，最终 TARGET_FOUND 由
verification 出。两次真机会话一次走 PRESENT、一次走 POSSIBLE，**所以任何只覆盖 PRESENT
的处理都是错的**。

**地图三层容量**（别把第三层当第一层）：
SLAM 权威地图 → 桥体素缓存（`max_global_voxels=300000`）→ 浏览器显示（`max_web_points=50000`）。
`web_display_points` 是显示采样数，**不是** SLAM 地图点数（§14 明文禁止混用）。

**relay QoS**：`/go2w/slam/web_map` = RELIABLE + TRANSIENT_LOCAL + KEEP_LAST(1)，latched。
`/go2w/slam/odom_base` = **BEST_EFFORT**，订阅端用 RELIABLE 收 0 条。
