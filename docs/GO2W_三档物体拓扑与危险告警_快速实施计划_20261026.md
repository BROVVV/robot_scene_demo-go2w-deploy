## 1. 用户要什么

完成以下四件事，形成一个能直接使用的版本：

1. 将识别到的物体分为固定地标、暂时静止物体、动态或高动态倾向物体三档。室内外使用同一套逻辑。

## 4. 三档规则与默认实现

### 4.1 档次定义

| 值 | 中文 | 室外示例 | 室内示例 | 持久入图 |
| --- | --- | --- | --- | --- |
| `fixed` | 固定地标 | 树干、建筑、固定路灯、固定护栏 | 立柱、门框、固定橱柜、固定设备 | 是 |
| `semi_static` | 暂时静止 | 停车、静止纸箱、可移动垃圾桶 | 桌椅、沙发、落地盆栽、纸箱 | 是 |
| `dynamic` | 动态或高动态倾向 | 行人、动物、行驶车辆 | 人、宠物、运行中的移动机器人、正在被推的椅子 | 否 |

规则优先级：可靠的运动证据 > 高动态倾向类别 > 固定属性与静止证据。

- 人和动物即使当前站着不动，也归第三档。
- 椅子、纸箱不因“可以移动”就归第三档，静止时属于第二档。
- 车需要区分停放与行驶；不能全部过滤，也不能全部保留。
- 固定地标采用保守词表。不能把所有柜子、所有设备都直接视为固定；属性不足时按可移动物体处理。
- 门框可以是固定地标，活动门扇按实际状态处理；盆栽不能直接按树干处理。
- 树叶摆动不应直接把整棵树判为动态，优先用稳定主体位置和连续证据。
- 室内/室外标签不直接决定物体档次，不设定三档数量比例。画面中没有第一档或第三档时，对应数量为零是正常的。

### 4.2 最小可用的跨帧跟踪与运动判断

新增一个轻量共享模块，例如 `app/spatial/object_mobility.py`，用简单的数据类和函数完成，不引入复杂跟踪平台。

处理顺序：

1. 检测并取得当前帧物体、深度位置、采集时间。
2. 在任何持久化过滤之前，为全部物体维护短期轨迹，包括最终不能入图的第三档。
3. 用类别兼容、空间距离与图像框作为关联依据，采用一对一匹配；复用现有匹配工具。持久物体 ID 仍由原物体地图管理。
4. 用图像采集时刻的位姿补偿机器狗运动，计算同一物体多次观测的位置变化。
5. 得到档次、判断理由和入图资格，再调用现有持久地图更新。

不要用图像框中心变化直接判运动。机器狗前进和转弯时，固定物体也会在图像中移动。

优先在连续 `odom` 坐标中估计短时运动。如果现有接口只方便取得地图坐标，必须在地图重置、坐标校正或定位跳变后清空对应运动窗口，不能把坐标跳变算成物体运动。持久位置继续使用既有地图坐标。

默认起点参数如下，集中配置，允许实施时根据已有代码进行小幅调整：

- 稳定确认：至少 3 个不同采集帧，时间跨度至少 2 秒。
- 稳定位移范围：约 0.15 m，结合有效深度和定位质量。
- 运动候选：补偿后位移超过约 0.25 m，且速度超过约 0.15 m/s。
- 连续 2 次有效运动证据后确认动态；确认前暂缓写入新位置。
- 停车或被搬动的椅子重新入图：持续稳定至少 3 秒，并满足稳定观测次数。

这些是实现起点，不是全距离通用精度承诺。无可靠位置时不能仅因画面变化宣布“已运动”，也不能把“没有测到运动”当作静止证据。

初次观测或证据不足时，令 `mobility_class=null`、`mobility_state=pending`，显示“待判定”，暂不进入持久图。待判定不是第四档。语义明确的人、动物可以立即判第三档。

为获得相邻时刻的判断证据，优先处理最近采集帧，并在出现新物体或运动候选时短时提高其采样优先级。不要仅用相隔很久、视角完全不同的稀疏关键帧硬算速度。第一版复用当前检测结果，不要求新训练一个检测器。

### 4.3 状态转换与已有节点

- 物体转为第三档：通过短期轨迹与持久 ID 的关联找到已有节点，将其设为不参与当前拓扑，撤下关联边；原始历史记录可以保留。
- 所有观测都被过滤时，也要发布新的空图或减小后的图，不能保留上一版非空图。
- 物体重新稳定：有足够身份依据则更新原 ID；不能确认同一身份时创建新节点，旧位置保持无效，不能同时留下两个有效副本。
- 第一档不因为短时间离开视野而删除。
- 第二档保存最近观测时间；默认 300 秒未复见标为陈旧并淡化显示，时间可配置。单纯离开视野不能宣称“已搬走”。
- 再次清楚观察原位置且目标确实不在，或已跟踪到它移动时，撤下旧节点。遮挡不能算缺失证据。
- 原有历史节点没有新分类字段时显示“待复核”，不静默把全部旧节点归到第一档或第二档。

## 5. 数据字段：只补必要信息

优先向现有对象记录增加以下字段，不另建一套重复实体库：

```json
{
  "mobility_class": "semi_static",
  "mobility_state": "stationary",
  "mobility_reason": "连续观测位置稳定，属于可移动家具",
  "mobility_confidence": 0.85,
  "topology_eligible": true,
  "is_hazard": true,
  "hazard_rule_id": "demo_box",
  "hazard_label": "实验危险物体",
  "hazard_event_id": "hazard_001"
}
```

`mobility_confidence` 可以是明确记录依据的规则分数，不要称为模型校准概率。首次时间、最近时间、物体 ID 和坐标复用现有字段。

字段必须贯通：检测/跟踪结果 → 持久实体 → `to_dict()` → 对象显示过滤 → 拓扑快照 → API → 前端。重点检查使用白名单挑字段的函数。

同一个有效节点只保留一份物体身份。危险属性附着在该节点上，不额外制造一个“危险纸箱节点”和一个“普通纸箱节点”。

## 6. 遥控拓扑数据接线：采用直接方案

采用以下默认方案，避免为接入遥控模式重构搜索服务：

1. 遥控进程复用 `SemanticObjectMap` 和现有关系存储，生成对象拓扑。
2. 在已有遥控 runtime 目录旁增加一个 `semantic_topology.json`，使用现有原子文件写入方式。
3. 快照包含 `session_id`、`map_epoch`、真实生成时间、递增 `revision`、`object_topology`、当前检测列表、有限长度的近期告警列表和处理延迟。
4. 增加只读 `GET /api/mapping/state`，读取当前配置指向的遥控快照，返回前端需要的 `graph.object_topology` 等字段。
5. `display_only` 遥控模式下，拓扑页和物体列表从该接口读取；搜索模式继续走现有 `/api/search/state`。
6. 前端每约 1 秒轮询遥控状态，按 revision 更新图；无需本轮新做一套 WebSocket 服务。
7. 图节点变化、边变化、档次变化、危险状态变化或有效性变化均推进 revision。历史回放不被实时轮询覆盖。

快照路径由启动脚本传给生产者和读取者，不能两端各写一个默认目录。两种运行模式不把旧图和新图混合。

地图会话切换时，清掉旧坐标对应的短期跟踪和当前图状态。只沿用现有 session/epoch 机制，不为此新建地图版本管理框架。

告警和实时检测不能依赖“已经有有效地图节点”才返回。定位暂时失效时，页面仍需看到当前检测和危险提示。

## 7. 关系图：让蜘蛛网有真实依据

复用 `object_relation_store.py`、`geometric_relation_extractor.py`，遥控模式不需要启动 PlaceGraph、frontier 或自主搜索。

第一版只完成以下关系：

- 已有且有证据的几何/语义关系，例如位于其上、包含、邻近。
- `near`：有可信位置，距离满足配置阈值。
- `co_visible`：两个对象在同一真实采集帧共同出现，表示共同观测，不能解释为可通行。

默认邻近阈值可设室内 2 m、室外 5 m，通过运行配置选择；不必为此新增一个室内外分类模型。不确定环境时采用保守默认值。

每个节点默认保留距离最近的最多 4 条普通邻近边；共现边也限制数量，优先保留反复出现且较近的对象对。明确的特殊关系可以另行保留。

- 不自连，不重复保存无向边，边两端必须是当前有效节点。
- 没有位置时不能按距离造 `near`；没有共同观测证据时不能造 `co_visible`。
- 不为了全图连通而用最小生成树强连不同房间或不可见区域。
- 使用稳定节点 ID，在重复观测中逐步把真实相连的局部图连起来。
- 稳定关系用实线，共现关系用细虚线，悬停显示含义。

## 8. WebUI 网状布局

在 `search_map.js` 里替换现有 BFS 分层布局，保留现有 SVG 渲染与交互基础。

实施默认：先查看项目是否已经带本地力导向库；有就复用，没有就实现紧凑的弹簧吸引、节点排斥和碰撞分离。不要为了布局引入整个新前端框架，不依赖在线 CDN。

必要效果：

1. 节点自然分散，围绕关系形成蜘蛛网，不按竖列或层级树排列。
2. 保存旧节点坐标，新节点在邻居附近出现；增量更新只做有限次数松弛，布局稳定后停止计算。
3. 节点框和标签尽量不重叠；不同连通区域分组摆放。
4. 第一档蓝色，第二档橙色，危险节点红色并加警告图标；危险节点仍显示原档次徽标。
5. 第三档和待判定对象显示在“当前检测”列表，不进入对象图。
6. 支持现有缩放、平移；增加节点拖动并固定，提供恢复自动布局按钮。
7. 点击节点显示类别、档次、原因、最近观测、危险信息；截图已有则复用，没有则显示当前可用证据。
8. 普通边不常驻大量文字，悬停或选中后显示，降低线团感。
9. 显示处理延迟、待处理关键帧数和最后更新时间。旧结果不能显示成“刚刚检测”。

图布局坐标只用于显示，不得写回真实物体位置。更新颜色与文字不能仅依赖节点 ID/边集合的布局指纹，否则危险状态变化可能不上屏。

## 9. 危险要素：第一版直接做可配置实验规则

### 9.1 默认可演示规则

新增一个简单 YAML，例如 `configs/go2w/semantic_mapping.yaml`，集中放运动、拓扑和危险规则。优先复用现有 YAML 加载方式。

默认启用实验规则：纸箱为实验危险物体，页面明确显示“实验模式：纸箱”。这是类别匹配，意味着匹配到的纸箱都算实验危险，不声称能自动区分两个外观相同的箱子。

配置至少支持：

```yaml
hazard:
  enabled: true
  demo_mode: true
  allow_indoor_demo: true
  confirm_observations: 2
  repeat_sound_cooldown_s: 30
  rules:
    - id: demo_box
      enabled: true
      labels: [cardboard box, carton, 纸箱]
      display_name: 实验危险物体
      color: null
```

标签匹配使用中英文归一化和明确别名，避免拿子串随意匹配。规则可改成椅子；如果设置颜色，必须存在可靠颜色证据才确认，缺少颜色字段不能按匹配成功处理。

危险规则词必须主动加入检测 prompt，不能只等 RAM++ 恰好返回纸箱类别。对齐现有分组检测和词表去重方式。

本轮不强制实现 ArUco、二维码或参考图片识别。如果用户后续明确要求“只识别某个特殊箱子”，再增加唯一标记规则；不要为了暂未确定的特征扩大本轮工作量。

### 9.2 告警与节点处理

- 第一次可信匹配立即显示“疑似实验危险”；连续 2 个不同新帧匹配后成为正式告警。
- 告警在动态过滤和地图定位过滤之前判定，第三档或深度缺失也能提示危险。
- 第一、第二档且位置有效：复用物体节点，节点、标签和相关详情标红。
- 第三档：显示实时危险告警和事件，不创建持久对象节点；稳定转为第二档后再落图。
- 位置暂不可用：告警显示“位置待确认”，不能用机器狗位置代替物体位置。
- 按规则 ID 和物体跟踪身份去重；取得持久 ID 后关联原事件，不重新报警生成重复事件。
- 同一目标连续可见时只更新事件；按配置限制重复声音。另一件危险物体仍产生独立事件。
- 短时遮挡或漏检不立即宣布危险解除，显示最近观测时间或“暂未复见”。
- 页面顶部告警条、危险事件列表和声音提示都要接通。浏览器通常要求用户交互后才能播放声音，增加一次性的“启用声音”按钮；静音只影响声音，不移除红色标签。
- 声音用浏览器 Web Audio 生成即可，不增加音频服务。
- 将事件和必要截图写入当前会话目录，便于回看；不新建数据库。

正式用途以室外为主，当前允许室内实验。若用户没有提供可靠的场景判定方式，不根据模型一句“室内”直接屏蔽危险告警。

## 10. 实时性：先解决现有瓶颈，不承诺虚假帧率

保留当前采集线程与推理线程分离、单实例检测器和有界队列。

- 在线处理优先最新观测，避免排队几十秒才显示当前危险。
- 旧关键帧继续用于有预算的补图；补图结果携带原采集时间，不更新当前运动判断、不覆盖最新检测，也不作为当前新危险再次响铃。
- 最简实现可以在原队列中优先取最新帧，间隔处理一张旧关键帧；数据过期时丢弃并记录数量，不另造任务调度系统。
- 新物体和运动候选获得短时连续观测，固定地标可低频更新。
- 不让云端 VLM 调用阻塞普通物体入图。需要属性复核时异步进行，第一版规则能够独立完成演示。
- 重复采集到同一源帧不能累计为多次确认。跟踪估计可以平滑显示，但不能把预测帧冒充检测证据。
- 先复用当前检测器，完成链路后只针对实测最慢的一个明显环节做小范围优化。不要启动模型选型和训练项目。

UI 约 1 秒读取一次新状态只是展示刷新频率，不等于检测器每秒识别一次。交付时如实报告实测一次完整识别耗时和从采集到显示的延迟。

## 11. 推荐实际修改顺序

按以下顺序连续实施，中途不提交重复计划：

1. **先接通遥控拓扑。** 复用现有遥控物体地图生成关系快照，增加 API，让无搜索任务时也能看到物体与边。
2. **加入三档分类。** 短期跟踪放在入图前，增加状态字段和动态撤图逻辑，复用到已有持久化入口。
3. **接通危险规则。** 默认纸箱可演示，完成检测词注入、事件去重、节点标红和声音提示。
4. **调整网状布局。** 复用现有页面，改布局、图例、详情和告警样式。
5. **处理明显延迟。** 优先最新帧，保证历史补图不污染当前状态。
6. **完成最小验证与交付。** 修复直接遇到的问题，给出准确启动方式。

新增文件建议控制在：一个运动分类模块、一个危险规则模块、一个 YAML。拓扑发布尽量放入现有 worker 和关系模块；确实使文件更清晰时可拆出一个小辅助文件，不以文件数量代替设计判断。

## 12. 只保留三项必要验证

不安排多轮验收，不要求跑全仓测试，不新增大批测试文件。完成修改后集中做一次：

### A. 静态与启动检查

- 验证配置能加载、只读 API 返回真实遥控拓扑快照、前端读取该接口。
- 不把构造的 JSON 或 mock 数据称为真机识别成功。

### B. 一个小型离线样例

用同一个短脚本或仓库现有回放机制串过实际处理函数，覆盖：固定物体、静止椅子、人、椅子移动、危险纸箱。

确认：前两类能入图，人不入图，移动椅子撤下，危险纸箱产生一个事件且标红。尤其要覆盖“已有物体转动态”，不能仅验证新的人进不了图。脚本无需扩展成测试框架。

### C. 一次短现场演示

用户已明确允许启动时，启动只读遥控建图，由用户持实体遥控器移动机器狗。观察一次前进/转向、行人经过、纸箱出现和节点刷新即可，不主动发送机器狗运动命令。

没有用户配合移动或现场条件时，完成所有可独立完成的修改、页面验证和静止检查，准确列出尚未验证的动态效果；不能因为缺一次演示就停止编码，也不能编造通过结论。
