## 发现的退出问题与修正

冻结08在客户端关闭三条视频连接后仍留下HTTP请求任务，SIGTERM等待不能进入应用收尾，最终夹具强杀，实际worker PID记录未清理。run04保存了任务栈及失败报告；新增完整帧/半帧断开两项真实HTTP回归在08原文件上均复现失败（9.85秒）。

根因定位于缓存头的BaseHTTPMiddleware包装与流式断连处理组合。改用纯ASGI缓存头中间件，仅修改原有页面/静态资源/管理接口的响应头，直接传递流式receive/send；保留原视频生成器的断连轮询和全部缓存头规则。电脑当前Uvicorn宣告ASGI2.4却在断连后静默丢弃send，不能仅依靠发送异常结束生成器。尝试只移除轮询或仅移除包装但没有轮询均未解决，相关失败记录保留，不把中间尝试写成通过。

最终run07完整链路通过：三次图像/深度、停流恢复、只读拒绝和正常收尾均通过。Web进入lifespan shutdown、实际worker退出0且PID文件删除，无强杀；Web退出-15为当前Uvicorn完成收尾后重新触发所请求SIGTERM的行为，已核对安装代码，不能把-15本身当作未收尾。记录为 `acceptance_20261110_camera_ros_web_pc/run07/report.json`。
