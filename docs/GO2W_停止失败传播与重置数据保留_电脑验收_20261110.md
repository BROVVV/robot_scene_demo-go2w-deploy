# 停止失败传播与重置数据保留：电脑验收（2026-11-10）

本轮继续用户要求的电脑端测试，不连接或启动机器狗，不运行SDK或ROS运动链。测试复制脚本到pytest独立临时项目，只操作夹具文件及测试创建的进程。实际项目运行数据、冻结03、机器狗install和原电脑依赖均未改。

## 复现的问题

正式恢复不能只看“重启命令返回了”，旧Web/TF消费者若没有停止，不能清空数据后再启动新会话。原脚本有以下不一致：

- stop_all.sh把Nav2停止失败仅当警告；只要二维定位停止成功，最终仍可返回0。Nav2停止脚本缺失时也可返回0；非可执行但可读的脚本被跳过，尽管调用方式本来就是bash。
- reset_webui_runtime.sh自主搜索分支用 `|| true` 忽略Web停止失败，随后可能归档、清空并启动新会话。
- Nav2停止失败时，重置监督脚本立即退出，未继续尝试其重置范围内的二维定位清理。

10项新增夹具测试先在旧代码运行，5失败/5通过，失败日志保留。失败检查不仅看返回码，也验证停止顺序、原数据字节及是否调用新启动入口。

## 修改

全量停止按可读性调用Nav2/二维停止脚本，累计失败，仍尝试其余层清理；任何一层失败或缺失都返回非零，不报告完整停止成功。

自主搜索重置累计Web、Nav2及清图动作所需的二维停止结果。只要失败，保留现有地图/对象/拓扑/搜索状态，不进入清空或启动步骤；锁与临时所有权标记仍由原trap正常清理。只清对象依旧保留地图和定位进程；遥操分支的标记保留/恢复方式不变。正常重启参数不含--enable-motion，实际启动入口ENABLE_MOTION仍默认为0。

## 验证

17项测试全部通过，包含新增10项、原运行时管理3项及原二维停止4项：

- Nav2错误、缺脚本、二维停止错误均令整体失败，且尝试其他相关停止层；可读但无执行位的脚本正常通过bash执行。
- Web/Nav2/二维各停止失败时，当前夹具数据逐字节保留，启动入口未被调用，锁释放。
- 正常清图按停止→归档→清空→只规划重启顺序工作，归档与原数据字节相同。
- 只清对象保留地图，不停止定位；遥操对象清理失败后，三个.reset_preserved所有权标记均恢复。
- 原二维停止的真实测试子进程覆盖孤儿组清理、外来PID拒绝及独立floor overlay退出；不扫描或停止真实项目进程。

两个脚本通过bash语法检查，Python测试通过3.8语法解析，原PC运行时管理/设置导入检查通过，没有依赖安装或升级。证据与当前电脑检查点在 `/home/mxt/robotscene_release_stage/acceptance_20261110_reset_contract/`。
