## 1. 本轮最终目标

机器狗在空旷工业园区由实体遥控器驾驶，系统同时完成：

- 二维地图持续更新，真实物体按地图坐标叠加。
- 识别适合园区的稳定地标，减少室内词表造成的漏检。
- 物体稀疏时，用真实经过地点形成综合拓扑骨架；保留原纯物体视图，不伪造物体凑数量。
- 保留三档过滤、跨视角连边和分档重访更新。
- 更稳定地发现涂在管道上的荧光绿色史莱姆，提示“模拟泄漏危险信号”，确认后标红和报警。
- 史莱姆定位困难时仍给出视觉提示；有可靠位置时落图，并与对应管道和同一事件关联。
- 跨视角、短时漏检、SLAM 回环和重访后，不反复生成重复危险节点。

这是指定材料与场景下的模拟信号识别。绿色外观规则不等于具备真实工业泄漏的普适识别能力；这个边界应体现在演示名称和交付说明中，不需要新增审批流程。

## 3. 优先修复的问题

### 3.1 园区词表与调度

当前危险词和普通检测词合并后使用 `[:16]`。即使 YAML 写了更多地标词，排在后面的词仍可能不被检测。危险词靠前又进一步占用普通地标名额。

当前 `use_ram_scene_terms=false`，普通物体主要依赖预设词表。关闭有其原因：以前泛化词曾产生背景误检，不要为增加节点简单全量打开。

### 3.2 管道上下文过于依赖当前框

`require_pipe_context=true` 时，没有本帧管道框的候选直接被过滤。因此即使颜色很明显，只要管道暂时漏检，也无法形成确认信号。

目前 `_boxes_near()` 仅判断候选矩形与扩张后的管道矩形相交。一根斜管道的框中可能有大量背景，草木、绿色标识也可能落入框内。

`require_semantic_context=true` 不代表必须同时检出“泄漏”：当前有管道框即可通过该分支。这本来是颜色补漏的目的，但不要把一次管道框与颜色交集描述成多种独立模型共同确认。

### 3.3 小色块和光照

当前最小面积是整幅画面比例 `0.0008`，最小边长 6 像素，固定 5×5 开运算。远处史莱姆投影变小、细流痕变窄时，有可能在增强阶段被删掉。

开运算先腐蚀再膨胀，本来就会移除小前景结构，因此固定核对小目标的影响需要结合目标像素大小处理。[OpenCV 官方说明](https://docs.opencv.org/4.12.0/d9/d61/tutorial_py_morphological_ops.html)

### 3.4 深度回退尚非“管道表面辅助定位”

当前 mask 深度无效时，使用的是普通框内采样。它可能取到背景或其它表面，不等于已经实现“借用该处管道表面深度”。

另一个需要修正的字段：mask 定位路径当前统一写 `depth_source=sam2_mask`，HSV 生成的 mask 也可能被这样记录。应保留实际 mask 来源。

### 3.5 两帧确认与事件身份

目前 `HazardMonitor.observe()` 累计不同 `frame_id` 的出现次数，没有严格的近期连续证据窗口；两次相隔较久的命中也可能累计。

短期重绑定允许使用图像框 IoU，机器人大幅转向后，相似屏幕位置不一定是同一处泄漏。同一管道也可能有两个不同色块，不能只按管道 ID 合并全部事件。

## 5. 园区感知与稀疏拓扑

### 5.1 增加工况配置与词组轮换

保留室内配置，新增 `industrial_park` 配置。危险规则独立于室内外词表；室内仍可做史莱姆演示。

词组建议：

- 固定设施：lamp post、fire hydrant、sign、electrical cabinet、pillar。
- 建筑局部：building entrance、door frame、building corner、固定设备。
- 绿化：tree trunk、独立树木。
- 工业设施：storage tank、pipe support、valve、pump、equipment cabinet。
- 可移动物体：parked car、truck、trash bin、pallet、container、traffic cone。
- 动态类别：person、dog、cat 等，继续用于实时显示和第三档过滤。

保留每轮必查的管道/危险词槽，其余词按组轮换；一组溢出时排到下一轮，不能永久截断。显示或记录本轮实际词表，便于判断到底问过哪些类别。

GroundingDINO 本身使用图像加文本输入，官方建议类别词以句点分隔；沿用项目现有提示词构造和英文检测词、中文显示名分离机制。[GroundingDINO 官方说明](https://github.com/IDEA-Research/GroundingDINO#-explanationstips-for-grounding-dino-inputs-and-outputs)

第一版不自动全量启用 RAM++。需要补类别时可低频发现，再经过独立物体词过滤和检测确认；猜测出的名称不能直接建节点。

### 5.2 大结构与远目标

- 全景大建筑、长围栏和长管道不必每次都当成一个中心点；优先选入口、支架、阀门等可重复定位的局部地标。
- 当前大框面积门对大型管道等结构要分类处理。可接纳为上下文候选，但不能因此自动将满屏背景作为持久物体。
- 普通物体 RGB-D 定位默认最大 8 m，增加类别词不能解决超距深度缺失。
- 确需远距落图时复用现有 RGB—激光融合，检查时间与外参、前景点数量和分布；没有可信点时保留“待定位”。不要单纯把深度上限调成几十米。
- 局部裁剪可提高已获得图像中小目标的处理分辨率，但不能创造原图没有的细节；先对管道候选区域低频使用，不把全画面无条件切成大量块。

### 5.3 地点骨架是单独的综合视图

保留纯物体拓扑，新增或启用“园区综合拓扑”显示层：

- 地点节点来自真实定位轨迹的代表位置、转弯和已观测入口附近。复用现有 PlaceGraph/关键帧能力；只有证据充分才命名为路口，普通轨迹点称“观察点”。
- 地点节点按实际走过的连续轨迹连接，不穿过定位丢失区间硬补边。历史走过不等于现在必然可通行。
- 物体通过地图位置与真实观察记录挂接到附近地点，沿用持久 object ID。
- 地点节点用不同形状，明确不是物体检测结果；纯物体 API 和原对象关系定义保持清晰。
- 长直道以位移阈值稀疏采样，例如先按 8 m 一个代表点，转弯或新区域增加点；不按每帧产生地点。
- 园区中不必把相距几十米的物体强行直连。中间用地点骨架连接，物体边继续保留真实局部关系。

## 6. 史莱姆候选优化：更容易发现，但不把全场绿色都当危险

### 6.1 管道先成为稳定的上下文

- 管道词与危险词共同属于优先槽，`pipe / pipeline / industrial pipe` 做别名归一化。
- 用当前检测管道 mask 约束色块，优先于矩形框相交。缺少 mask 时保留框作为较弱证据，而不是等价确认。
- 对大管道候选，普通物体的大框过滤不能在进入增强器之前把上下文全部删除；将“能提供管道上下文”和“能作为持久节点”分开判断。
- 本帧管道漏检时，可短期复用已验证管道的跟踪 mask/ROI，但必须经过当前图像跟踪或有几何依据的重投影。禁止直接复制上帧框位置。
- 默认缓存最长约 8 秒，并要求跟踪质量足够。超时或大幅转向后跟踪失败，就只保留疑似候选，触发下一轮局部管道复核。
- 重投影得到的范围只说明去哪里找管道，不等于管道当前一定可见；需要新的图像证据后才能作为确认支持。

### 6.2 在管道表面附近分割颜色

保留当前荧光绿色 HSV 默认值 `[32,105,70]–[92,255,255]` 作为初始配置，不直接大幅放宽成“所有绿色”。

候选生成分两级：

1. **全图宽松候选**：找可能的指定颜色区域，仅生成疑似提示或复核 ROI。
2. **管道局部确认**：在可靠管道区域内检验色块覆盖、局部对比和有效时序证据，满足后才触发模拟危险确认。

ROI 应是可见管道表面 mask 的小范围扩张，不是将整个管道外接矩形都视为表面。扩张量按管道像素宽度或有限局部尺度确定，不只按全图百分比无限扩大。

真实史莱姆会覆盖管道表面，管道分割可能在绿色区域形成孔洞；允许结合管道轮廓/前后帧或可验证表面几何补足局部区域，不能因 mask 不含史莱姆就全部漏掉，也不能任意填满背景。

色块判断增加两项轻量证据：

- 目标颜色与附近已验证管道表面形成局部色彩差异；大片绿色管道涂层不自动当作泄漏。
- 有有效深度时，色块与对应管道表面的深度应相容；绿色背景植物位于管道后方时不得借管道框升级为确认。

在颜色、位置、外观都非常相似时，绿色贴纸、绿色涂漆与史莱姆可能无法单凭这些规则区分。不要承诺“管道上任何绿色都能准确判断材质”；实验材料与管道需要明确反差，必要时使用已知涂抹区域作为实验约束。

### 6.3 适配像素大小，不盲目降低全图门限

- 将全图面积、ROI 内面积、最小有效像素数分开记录与筛选。小目标在局部 ROI 中处理，不仅依赖全图 `0.0008` 阈值。
- 对小色块使用 1×1/3×3 的轻量处理，较大色块再使用 5×5；必要时跳过会抹去细条的开运算，改用连通区域筛选。
- 使用连通区域及像素尺度选择核，避免固定 5×5 对所有目标一刀切。
- 原始颜色 mask 用于证据与定位。任何为补洞而生成的像素都单独标注，不能当作真实测得的颜色/深度证据。
- 取消“面积最大的三个候选永远优先”的单一倾向。候选上限保留，但排序优先管道表面匹配与时序一致，再考虑面积，并避免一根管道占满全部名额。
- 局部裁剪坐标和 mask 必须正确还原到原图，使用原图内参与深度对齐；不能把裁剪像素直接交给全图定位器。

## 7. 模拟危险确认与去重

### 7.1 候选、确认与位置分别判断

建议保留简单状态：

- `suspected`：出现颜色异常或语义泄漏候选，当前上下文尚不充分。
- `confirmed_demo`：满足模拟规则及近期多帧证据，发出正式演示告警。
- 位置另记 `direct / pipe_surface_estimate / host_only / unavailable`，不能因为没有精确深度就完全不提示。

确认建议采用“最近 3 次有效、唯一源帧中至少 2 次支持，且证据跨度不超过约 12 秒”的起点。若本机推理慢于这个窗口，依据实际源帧间隔调整，不能为了达标把旧帧算成新证据。

- 有效未命中在窗口中算未命中；检测未执行、图像失效或管道被遮挡标记不可判定，不能拿来无限维持确认资格。
- 长时间没有新证据时，已确认事件转为“待复查”，保留历史；新一次确认不能借用几分钟前单独一次命中。
- 同一源帧裁剪推理、HSV 和模型检测属于同一时刻的一组证据，不算多帧确认。
- HSV 生成的 0.8 一类分数是规则评分，不宣称为校准的真实泄漏概率。

### 7.2 事件绑定管道局部位置

复用现有危险事件 ID，增加可选 `host_object_id` 和管道上的局部异常位置/观测锚点：

- 去重优先使用同一规则、同一持久管道身份和相近局部异常位置。
- 一根管道上的两个明显分离色块保留两个事件，不按 host ID 全部合并。
- 转向后重新看到同一异常，复用事件并更新最近观测；不能仅凭屏幕框位置相似重绑。
- IoU 重绑定只允许在有连续图像跟踪依据的相邻视图中使用；跨视角优先地图/宿主局部位置。
- 短期未取得宿主 ID 时，用临时事件，关联到持久身份后合并；不要在合并前后重复响铃。
- 与地图 epoch、关键帧锚点绑定，回环时更新位置，不新建一个“另一次泄漏”。

## 8. 深度无效时，真正接上管道表面辅助定位

定位顺序明确为：

1. **色块自身深度。** 使用颜色 mask 中足够、分布合理的有效点，输出直接定位。
2. **局部管道表面估计。** 从色块附近且属于同一可见管道表面的区域取样，估计沿该色块像素视线的深度；不要取整根管道的平均深度或中心位置。
3. **经标定的激光辅助。** 已有 RGB—激光融合能可靠匹配到同一表面时使用；稀疏点或多个表面无法区分就不作精确估计。
4. **仅关联宿主或未定位。** 标红宿主管道并注明异常局部位置待确认，或仅显示图像告警。不往地图原点或机器人位置放点。

第二步的采样范围：局部色块周边、排除无效值和明显前后背景、检查深度离散程度与表面连续性。曲面管道不满足局部近似时，宁可只关联宿主，不做过度几何拟合。

通过周围管道估计的位置必须标记 `pipe_surface_estimate`，并显示为近似位置；不能与史莱姆真实有效深度混为一谈。

这条规则假定材料贴附在管道表面，不能对悬垂液滴或地面液体直接套用。对本轮涂抹史莱姆实验先实现附着表面场景。

修正来源字段：分别记录 `hsv_slime_mask`、实际 SAM2 mask、`bbox`、`pipe_surface_estimate` 和激光来源。把颜色分割与深度来源分成不同字段更清楚，避免用一个字段同时表达两件事。

## 9. 与三档物体、拓扑和二维地图整合

- 工业设施只有在固定安装证据足够时归第一档，不能把任何叫 pipe 的散放物都当作固定地标。
- 静止的附着史莱姆可以保留为第二档模拟异常对象并通过 `attached_to` 关联管道；使用稳定局部位置，不要求像椅子一样具有固定外形。
- 若液体/材料正在移动，按现有规则不建立第三档持久物体；危险事件仍可附着在固定管道上并使管道标红。这是危险事件属性，不把动态液体偷偷永久化。
- 宿主管道变红是其危险状态聚合；局部异常标记使用同一事件，避免复制出多个相同泄漏节点。
- 纯物体视图仍只含物体；综合视图可另含地点。地方、物体、危险事件的类型和图例要明确。
- 二维地图、对象拓扑共用 object/event ID、map epoch 和当前语义版本。精确异常显示红点，近似位置显示带估计说明的标记，host-only 只高亮管道。
- 物体层已有跨视角 `near/spatial_neighbor` 继续按真实坐标更新，不能为室外效果直接把半径无限放大。

## 10. 保留并补齐之前的地图更新要求

实施时逐项确认已有接线，不重复开发：

1. 遥控入口同时启动/复用独立二维 SLAM 和语义 worker，不启动自主运动。
2. 物体使用图像采集时刻的 `map` 坐标，不能把 `pslam_map` 直接改名；地图和物体身份相同。
3. 完整显示 OccupancyGrid 的自由/占用/未知，支持 origin 平移、旋转和地图扩展；z 不影响二维落点。
4. 同一有效拓扑物体在二维图有同 ID 标记，不因旧三维框阈值再次静默删除。
5. 固定地标长期保留；第二档按重访、视野、遮挡和有效缺失证据更新；第三档不进入持久图。
6. 原位置空出的判断按 object ID，不能按“椅子/管道”整个类别批量删除。未看见或颜色暂时过曝不等于风险解除。
7. 第二档位置变化后采用新的稳定位置段，旧帧不能把位置拉回或恢复已撤下节点。
8. 回环修正通过关键帧锚点更新节点、地点骨架、异常位置和关系。
9. 地图源更新与视觉推理独立；WebUI 显示真实采集时间和处理延迟。
10. 地图、对象、拓扑和事件分别保存，语义文字不烧进 PGM 占据格。

史莱姆被清理后的复查应同时要求：对应管道表面重新可见、颜色检测确实执行、图像质量可用，并连续取得有效未命中。状态可记“模拟异常已未复见”；不能仅靠超时宣布真实管道安全。

## 12. 配置和调参方式

保留现有 HSV 默认值、事件 ID 与规则 ID，新增参数集中到现有 YAML：

- `scene_profile: industrial_park` 与地标词组。
- 危险/管道词槽优先级和普通词组轮换间隔。
- 管道上下文最大有效年龄、ROI 扩张与跟踪质量要求。
- 不同像素尺度的形态学核、最小有效像素、局部色差条件。
- 确认窗口：起点为最近 3 个有效唯一源帧中 2 次，最大跨度约 12 秒。
- 深度模式与近似位置质量条件。
- 地点采样距离、转弯采样条件和综合视图开关。

如果现场光照使默认颜色范围明显不适合，可用一张真实史莱姆画面选取区域，生成本场地 HSV 建议范围供配置使用。第一版只需简单取样工具，不开发复杂标定页面；不从整张草地自动学习“绿色正常/危险”，避免被背景带偏。

不要声称 `10×15 cm` 或固定距离保证识别。实际可见性取决于成像像素、视角、遮挡和光照，第一版以真实取景中足够明显的连续色块完成演示，再记录有效距离范围。

## 13. 最小验证：一次离线检查和一次真实材料短演示

对修改文件做语法/导入检查，然后复用现有史莱姆测试和小量回放，不新建大测试工程。

离线集中覆盖：

- 已有正例仍能产生 mask 和告警；管道外绿色、黄色背景、只凭 fluid spill 语义不能确认为模拟信号。
- 绿植位于管道大框内但不在可见表面时，不升级为确认。
- 管道短时漏检，有可靠跟踪时可继续积累有效证据；失去上下文后保持疑似，不复制旧框硬确认。
- 小色块不被固定大核无条件抹去；裁剪坐标还原正确。
- 两个相隔很久的命中不能当作短时两帧确认；同一帧多分支不能重复计数。
- 自身深度无效时能区分可靠管道估计、仅宿主和未定位；不把背景深度写成真实异常位置。
- 同一管道两处异常不误合并；转向/回环后同一处异常不重复。
- 普通园区词组没有因危险词优先而永久不执行。

现场只需要一次短演示：在真实管道上放置荧光绿色材料，近处观察、改变角度、经过有绿色背景的位置、离开再重访；条件允许时清理材料后复查。用户操作遥控器，不由 AI 发送运动指令。

现场结果分别记录“检出”“确认”“定位”“落图”“事件去重”是否成功，不只写“程序 running”。没有放置实物时，说明缺少正目标证据，不以无误报代替命中验证。
