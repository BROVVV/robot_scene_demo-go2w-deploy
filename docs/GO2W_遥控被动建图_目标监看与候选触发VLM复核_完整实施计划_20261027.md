## 1. 结论与核心设计

该功能可行，且不需要复制一套自主搜索系统。正确做法是新增一条独立的“被动目标监看（passive target watch）”链路：

```text
WebUI 输入自然语言目标
        │
        ▼
一次性目标解析（类别 / 属性 / 关系 / 危险物类型）
        │
        ▼
目标词与关系锚点词进入当前检测器的高优先级词槽
        │
        ▼
遥控建图关键帧：Grounded-SAM 或 YOLOE-Seg 检测 + mask + RGB-D 定位
        │
        ├── 没有疑似候选 ──> 继续建图，VLM 调用数保持 0
        │
        ▼
候选门（类别、分数、框/mask、关系锚点、去重、冷却、预算）
        │
        ▼
有界异步 VLM 复核（最多 1 个在途 + 1 个待办）
        │
        ├── CONFIRMED：显示证据与可靠位置，标记目标
        ├── REJECTED：只排除本次候选，不删除普通地图物体
        └── UNKNOWN：超时/异常，不产生正例或负例

机器狗运动：始终由操作者使用实体遥控器完成
```

核心职责必须保持：

- 检测器负责候选召回与实例几何；
- VLM 负责颜色、状态、复杂关系和危险现象的最终语义复核；
- RGB-D/SLAM 负责位置；
- WebUI 只设置监看目标和展示结果；
- 实体遥控器负责全部运动。

## 2. 范围与非范围

### 2.1 必须实现

- 遥控建图 WebUI 增加独立“目标监看”输入、启用/更新、清除按钮。
- 支持普通目标、属性目标、关系目标和危险现象目标。
- 目标只解析一次；每个关键帧不重复调用文本模型。
- 当前选定的 `grounded_sam` 或 `yoloe_seg` 后端都能产生目标候选。
- 目标词和锚点词每轮优先保留，普通场景词继续按原计划轮换。
- 无疑似候选时不调用视觉 VLM。
- 有候选时异步复核，不阻塞关键帧采集、SLAM spin 或普通语义建图。
- 复核结果严格绑定目标代次、源帧、候选、原始图像和拍摄时刻坐标。
- WebUI 显示候选、复核状态、证据图、结论、置信度、原因、耗时和位置质量。
- 确认结果可在二维/三维地图上显示，但不得伪造坐标。
- 目标更新/清除后，旧 VLM 结果不能污染新目标。
- 增加配置、事件、诊断、单元测试、接口测试、离线回放和真机无运动验收。

- 不启动 Nav2，不生成或发送导航目标。
- 不改变机器狗运动控制权，不增加网页遥控。
- 不改变此前暂缓的自主搜索整体架构。
- 不把通用场景检测全部替换成 VLM。
- 不做“每隔几秒整帧 VLM 搜索”作为默认补漏。
- 不在一次遥控建图会话中热切换 Grounded-SAM/YOLOE-Seg 后端。
- 不把检测候选直接宣布为目标找到。
- 不因当前目标被 VLM 排除而从普通语义地图删除真实物体。
- 不把烟雾或透明液体的低可靠深度包装成精确 `map_xyz`。

## 4. 不可破坏的系统不变量

### 4.1 运动隔离

目标监看链不得依赖或调用以下任何内容：

- `/api/search/start`；
- `SearchSessionService.start_search()`；
- Task Agent/前沿规划/语义路线规划；
- Nav2 action/service；
- `/cmd_vel`、`/go2w/motion`、`/wirelesscontroller`；
- arm、stop、estop 或 Unitree 运动接口。

新增 API 是“感知配置写入口”，不是“运动控制写入口”。现有 display-only 运动硬门和启动自检必须继续通过。

### 4.2 VLM 调用纪律

- 空场景、无候选、候选门失败：VLM 调用数必须为 0。
- 每个候选先经过本地检测器和轻量规则门。
- VLM 最多 1 个真实在途请求；超时请求物理上仍占槽时，不得再并发启动新请求。
- 超时、网络错误、daemon 不可用均为 `UNKNOWN`。
- VLM 不得成为语义建图成功与否的硬依赖；VLM 故障时普通建图继续。

### 4.3 时空与身份绑定

每条复核必须绑定：

```text
mapping_session_id
target_generation
verification_sequence
frame_id
candidate_id
source_image_path
candidate_bbox / mask reference
capture_timestamp
camera_xyz
map_xyz（若当时真实可用）
map_epoch / transform provenance
detector backend / model
```

VLM 晚返回时只能更新这条候选的复核状态，不能用机器人当前位姿重新定位，也不能匹配到同类的另一个物体。

### 4.4 输出真实性

- `CONFIRMED` 必须来自成功 VLM 复核且达到置信门槛。
- `REJECTED` 必须来自成功 VLM 明确排除。
- `UNKNOWN` 不得写成 `ABSENT`。
- 没有可靠深度或变换时允许只显示相机证据，坐标字段保持 `null`。
- 低阈值目标候选不能绕过普通语义地图的持久化质量门。

## 5. 新增领域模型与状态机

建议新增 `app/perception/passive_target_watch.py`，承载纯 Python、无 ROS/FastAPI 依赖的核心模型与规则。

### 5.1 `TargetWatchSpec`

最少字段：

```python
@dataclass(frozen=True)
class TargetWatchSpec:
    raw_query: str
    canonical_name_zh: str
    target_type: str
    target_terms_en: tuple[str, ...]
    target_aliases_zh: tuple[str, ...]
    attributes: tuple[str, ...]
    colors: tuple[str, ...]
    relation_constraints: tuple[str, ...]
    anchor_terms_en: tuple[str, ...]
    negative_terms: tuple[str, ...]
    possible_confusions: tuple[str, ...]
    verification_mode: str
    resolver_source: str
```

`verification_mode` 至少支持：

- `object`：普通物体；
- `attribute`：颜色/材质/状态；
- `relation`：目标与锚点的空间关系；
- `diffuse_hazard`：烟雾、泄漏液体、史莱姆等弥散危险现象。

### 5.2 目标状态

```text
IDLE       没有目标
PARSING    正在解析输入
ARMED      目标已生效，等待候选
CANDIDATE  有候选但尚未提交/被预算限制
VERIFYING  VLM 请求在途
CONFIRMED  已确认
REJECTED   最近一次候选被排除，监看仍可继续
UNKNOWN    最近一次复核未得到结论，监看仍可继续
DEGRADED   VLM 不可用，但普通建图继续
```

`REJECTED/UNKNOWN` 不是会话终止状态。普通目标默认在首个确认后锁存，避免继续花费 VLM；危险现象目标默认继续监看新事件。行为必须可配置。

### 5.3 候选记录

每个 `TargetCandidate` 至少保存：

```text
candidate_id（同帧稳定且唯一）
target_generation
frame_id
source_object_id
persistent_object_id（可为空）
matched_term
detection_slots
detector_score
bbox_2d
mask_available
anchor_candidate_ids
verification_bbox
camera_xyz / map_xyz
spatial_quality / provenance
capture_timestamp
evidence_path
```

候选 ID 不允许只使用类别名；推荐 `frame_id + detection index + prompt hash`。跨帧冷却键优先用 `persistent_object_id`，其次使用目标代次加量化地图位置/框。

## 7. Web 后端与目标解析

### 7.1 新增 API

在 `app/manual_web_demo/web_server.py` 或独立 router 中增加：

```text
GET    /api/mapping/target-watch
POST   /api/mapping/target-watch
DELETE /api/mapping/target-watch
GET    /api/mapping/target-watch/evidence/{verification_id}
```

行为：

- `GET` 返回当前会话目标监看状态；
- `POST` 接收 `{ "target": "黑椅子" }`，在线程池中完成一次目标解析，写请求文件；
- `DELETE` 写入新 generation 的 clear 请求；
- evidence 接口只能通过状态快照中已登记的 `verification_id` 查找证据，且文件必须位于本会话证据目录，防止路径穿越。

这些接口在 `display_only=true` 时允许使用，因为它们只配置感知；所有运动/自主搜索入口仍必须 403。非遥控 mapping mode 下建议返回 409，避免操作错误会话。

### 7.2 目标解析策略

复用 `TargetProfileResolver`，但增加 `TargetWatchSpec` 后处理：

1. Web API 使用 `asyncio.to_thread()` 或 executor 执行解析，禁止阻塞 ASGI event loop。
2. 有 API key 时允许一次文本 LLM 解析；这不是视觉 VLM，不随关键帧重复。
3. 无 API key/解析失败时使用确定性 fallback，并将 `resolver_source`、`resolver_error` 返回前端。
4. 关系角色必须明确区分：
   - “饮水机旁边的凳子”：目标是 `stool/chair`，锚点是 `water dispenser`；
   - “挂着书包的椅子”：目标是 `chair`，锚点是 `backpack`；
   - 不能把位置提示物误当成目标。
5. 颜色和材质不能代替核心类别。`黑椅子` 的召回词至少包含 `chair`，可附加 `black chair`，最终黑色由 VLM 判断。
6. 烟雾/泄漏/史莱姆归入 `diffuse_hazard`，生成适当同义词和上下文词。

必须为以下输入写固定测试：

| 输入 | 目标词 | 锚点词 | 模式 |
| --- | --- | --- | --- |
| 黑椅子 | chair, office chair, black chair | 无 | attribute |
| 饮水机旁边的凳子 | stool, chair | water dispenser | relation |
| 烟雾 | smoke, visible smoke, steam | 可为空 | diffuse_hazard |
| 泄漏的液体 | liquid leak, fluid spill, puddle | pipe, valve 可作上下文 | diffuse_hazard |
| 史莱姆泥 | slime, green slime | pipe 可作上下文 | diffuse_hazard |

## 8. 检测提示词与后端接入

### 8.1 统一动态目标配置

当前 detector 在遥控建图启动时没有 target profile。为避免修改目标时重建 CUDA worker，给本地结构化检测器增加统一的动态配置能力，例如：

```python
configure_target(profile: TargetProfile | None) -> None
```

要求：

- Grounded-SAM 和 YOLOE-Seg 都实现或由公共适配器实现；
- 只更新后续请求使用的 target/anchor prompt，不重启进程；
- 在语义侧车的 `_detect_lock` 内更新，不能与正在写 JSONL 的检测请求并发；
- `clear` 后恢复纯场景建图词表；
- 不允许改变本会话 backend。

如果最终选择给 `detect_with_dynamic_terms()` 增加显式 `target_profile` 参数，也必须同时更新两种后端和契约测试，不能通过直接改私有属性凑合。

### 8.2 词槽与预算

每轮 prompt 预算仍由 `detection_schedule.max_terms_per_round` 控制，优先顺序固定为：

```text
当前目标核心词/组合词
  > 关系锚点词
  > 与当前危险目标直接相关的危险词
  > 原有全局 hazard priority_terms
  > 当前轮普通场景词
```

建议新增配置：

```yaml
target_watch:
  enabled: true
  max_target_terms: 6
  max_anchor_terms: 4
  reserve_scene_terms: 3
```

若预算不足，必须在事件中记录被截断的词，不能静默让某个目标词永远得不到检测。

YOLOE-Seg 请求使用：

- `target` slot：目标核心词和属性组合词；
- `anchor` slot：关系锚点；
- `scene` slot：场景轮换与通用危险词。

Grounded-SAM 必须生成等价的 slot 信息，不能只靠 label 字符串事后猜。

### 8.3 检测批次结构

不要继续让 `_detect()` 只返回一个已经过普通地图阈值过滤的列表。建议引入内部 `DetectionBatch`：

```text
raw_detections             检测器原始有效实例
mapping_detections         通过现有 0.35/面积门的普通建图实例
target_candidates          通过目标候选门的实例
target_anchors             同帧关系锚点
prompt_terms / slot_terms
diagnostics
```

要求：

- 普通建图继续只使用 `mapping_detections`，保持原质量门；
- 目标候选可使用稍低的独立阈值以提高召回，但只能触发 VLM，不能直接持久化或确认；
- 历史关键帧只允许补普通语义证据，不得触发新 VLM；
- `--smoke` 是否启用目标监看必须由显式参数决定，默认普通 smoke 行为不变。

## 9. 候选门与不同目标类型

### 9.1 公共候选门

候选至少满足：

1. `detection_slots` 包含 `target`，或命中经过规范化的直接目标词；
2. 达到 backend 专用候选阈值；
3. bbox 有效且面积不超过候选上限；
4. mask 若存在必须尺寸合法，但普通物体第一版不强制必须有 mask；
5. 不是明确 negative term/confusion；
6. 未命中同一目标/实体的冷却缓存；
7. 当前 VLM 预算允许；
8. 同帧最多取评分最高的 1～2 个。

初始配置建议（必须通过回放校准，不可散落硬编码）：

```yaml
target_watch:
  candidate:
    min_score:
      yoloe_seg: 0.20
      grounded_sam: 0.12
    max_bbox_area_ratio: 0.80
    max_per_frame: 2
    same_candidate_cooldown_s: 20
```

### 9.2 属性目标

以“黑椅子”为例：

- `chair/office chair` 足以成为候选；
- 检测器是否输出 `black chair` 只能增加排序分，不能成为必要条件；
- VLM 必须同时确认“是椅子”和“主要外观为黑色”；
- 白色、灰色或光照阴影明显的椅子应由 VLM 排除或给低置信。

### 9.3 关系目标

以“饮水机旁边的凳子”为例：

- 必须分别保留目标和锚点检测；
- 先做低成本几何预筛：同帧、合理像素距离/深度距离、框不完全无关；
- VLM 裁剪框使用目标框与最相关锚点框的并集，并增加上下文边距；
- 最终 marker 坐标取凳子，不取饮水机；
- 找到凳子但没有饮水机只能是普通候选，不能确认关系目标。

应把现有私有 `_verification_region()` 提取/包装为公共函数，并保留旧调用兼容，避免自主搜索回归。

### 9.4 烟雾、泄漏液体和史莱姆

这类目标不是稳定刚体，按以下策略处理：

- 烟雾：使用 `smoke/visible smoke/steam` 等开放词候选；复核区域较大，必要时整帧；不因雾状背景直接确认。
- 液体泄漏：使用 `liquid leak/fluid spill/puddle`；若同帧有管道/阀门，联合上下文复核。
- 史莱姆：继续使用现有开放词检测 + HSV 增强；普通绿色物体、黄色墙面或单独管道不能直接确认。
- 现有 `HazardMonitor` 的连续帧/管道上下文规则继续有效，目标监看不得绕开它制造危险告警。
- 若无法从 mask/depth得到可靠三维位置，结果保留为视觉确认；若能绑定固定管道，可报告“靠近管道”的锚定位置及质量，不能伪造液体中心坐标。

第一版不承诺通用 YOLOE/GroundingDINO 对所有真实烟雾和透明液体都有高召回。验收数据若证明候选召回不足，应在报告中明确提出专用烟雾/液体检测器需求，不能改成无条件高频 VLM。

## 10. 异步 VLM 复核

### 10.1 调用方式

遥控语义侧车通过 `SiliconFlowDaemonClient` 调用现有 Unix socket：

```text
runtime/go2w/siliconflow_vlm.sock
```

请求使用：

```text
mode=verify
target=原始中文目标
bbox=verification_bbox
frame_id=源帧 ID
extra_instructions=目标画像、属性、关系和否定约束
priority=realtime
```

不得把 API key 复制到状态文件、事件或 Web 进程返回值。

### 10.2 有界调度

复用 `AsyncVerifierManager`，配置建议：

```yaml
target_watch:
  verify:
    enabled: true
    max_inflight: 1
    max_pending: 1
    client_timeout_s: 12
    max_calls_per_minute: 3
    confirmation_min_confidence: 0.70
    cache_ttl_s: 120
    stop_after_first_object_confirmation: true
    continue_after_hazard_confirmation: true
```

要求：

- latest-wins 合并待办；
- 物理在途请求即使客户端超时也继续占用并发槽；
- 目标 generation 改变时清空待办，旧在途结果返回后按 stale 丢弃；
- 同帧/同实体/同目标缓存命中时不重复调用；
- rate limit 只延迟或丢弃复核，不影响建图；
- VLM 回调线程只更新受锁保护的目标状态和原子快照，不操作 ROS provider。

### 10.3 证据帧

当前 `semantic_frame.jpg` 会被后续帧覆盖，绝不能直接作为异步复核的长期输入。提交 VLM 前必须复制为唯一证据文件：

```text
outputs/remote_control_mapping/runtime/target_watch_evidence/
  tw_<session>_<generation>_<frame>_<sequence>.jpg
```

要求：

- 先复制成功再提交；
- 文件名只由服务器生成的数字/安全 ID 构成；
- 状态只保存路径引用，不嵌入 base64；
- 保留数量有上限，删除时不能删除当前在途或 Web 正在引用的证据；
- 清理范围严格限制在该 evidence 目录。

### 10.4 结论规范化

统一输出：

```json
{
  "status": "CONFIRMED|REJECTED|UNKNOWN",
  "is_target": true,
  "confidence": 0.91,
  "object_name_zh": "黑色办公椅",
  "reason_zh": "椅背与座面均呈黑色",
  "provider": "...",
  "latency_ms": 2680,
  "unknown_reason": null
}
```

判定规则：

- `is_target=true` 且 confidence 达到门槛才是 `CONFIRMED`；
- 成功响应且明确 `is_target=false` 是 `REJECTED`；
- 超时、异常、缺字段、身份不匹配都是 `UNKNOWN`；
- 低于确认门槛但不是明确排除时建议记为 `UNKNOWN`，而非强制 `REJECTED`。

## 11. 与语义地图、拓扑和事件的关系

### 11.1 不污染普通对象地图

目标监看结果建议作为 `semantic_topology.json` 中独立的 `target_watch` 区块发布，不强制给 `SemanticObjectMap` 增加大量任务态字段：

```json
{
  "target_watch": {
    "state": "CONFIRMED",
    "generation": 4,
    "raw_query": "黑椅子",
    "current_candidates": [],
    "confirmed_matches": [
      {
        "verification_id": "twv_0007",
        "frame_id": "180519",
        "persistent_object_id": "obj_012",
        "bbox_2d": [0.1, 0.2, 0.4, 0.8],
        "camera_xyz": [0.2, 0.0, 1.8],
        "map_xyz": [2.1, -0.8, 0.5],
        "spatial_quality": "METRIC_LIDAR",
        "confidence": 0.91,
        "reason_zh": "...",
        "evidence_url": "/api/mapping/target-watch/evidence/twv_0007"
      }
    ]
  }
}
```

若已有可靠 `persistent_object_id`，可在展示投影中给该节点增加 `is_target_confirmed`，但不要覆盖对象原始 label/category/status。

### 11.2 瞬时候选与确认 marker

- 未确认候选只在当前识别帧叠框，地图上最多显示临时空心 marker。
- `CONFIRMED` 且有可靠 `map_xyz` 才显示固定目标 marker。
- 没有 map 坐标时显示“相机证据，无可靠地图位置”。
- `map_epoch` 变化后，旧 marker 必须变为 stale/隐藏，不能叠到新地图。
- 关系目标同时显示目标与锚点关系文字，但 marker 主体位置使用目标对象。

### 11.3 事件

至少写入以下 JSONL 事件：

```text
target_watch_configured
target_watch_cleared
target_watch_terms_scheduled
target_watch_candidate
target_watch_candidate_suppressed
target_watch_verification_started
target_watch_verification_finished
target_watch_confirmed
target_watch_rejected
target_watch_unknown
target_watch_rate_limited
target_watch_stale_result_discarded
target_watch_degraded
```

每个事件必须带 session、generation、frame/candidate/sequence（适用时）、backend 和 host 时间；不得记录密钥或大块图像数据。

## 12. WebUI 设计

### 12.1 页面行为

当 `/api/status` 表明 `control.display_only=true` 时：

- 页面进入 mapping mode；
- 自主搜索“开始”按钮继续禁用；

- 禁止把 mapping mode 输入提交到 `/api/search/start`。

### 12.2 展示字段

至少显示：

- 原始目标与标准化目标；
- 解析来源（LLM/fallback）和解析错误；
- 当前 detector backend；
- 目标词、锚点词、属性/关系；
- 状态：等待候选/复核中/已确认/已排除/未知/降级；
- 最近候选 label、score、frame；
- VLM provider、置信度、原因、耗时；
- 调用预算与累计统计；
- 证据图；

候选框颜色建议：黄色；复核中：蓝色；确认：绿色；排除：灰色；危险确认：红色。颜色之外还要有文字/图标，不能只靠颜色表达状态。

### 12.3 轮询与缓存

- 继续复用 `/api/mapping/state` 轮询，可把 `target_watch` 嵌入该响应；
- 控制请求与即时状态也可通过独立 GET 获取；
- 所有响应和证据图使用 `Cache-Control: no-store`；
- 状态 revision 或 verification sequence 改变时更新界面；
- 页面刷新后能恢复当前同一 mapping session 的监看状态。

## 14. 进程生命周期与启动/停止脚本

### 14.1 启动

修改 `start_remote_control_mapping.sh`：

1. 解析目标监看配置并创建独立运行目录。
2. 为本次 mapping session 初始化空 request/state，不继承旧目标。
3. 预检 VLM daemon 所需解释器、socket 目录和凭据，但 VLM 不可用不应阻止普通建图启动。
4. 若 target watch 启用且 daemon 未运行，调用 `start_vlm_daemon.sh`；只有本启动器实际新启动时才创建 ownership marker。
5. 若 daemon 已存在且健康，复用，不创建 owner marker。
6. 把 request/state/evidence 路径传给语义侧车和 WebUI。
7. 启动输出明确显示：目标监看 enabled/disabled、VLM ready/degraded、检测后端。

不得因为目标监看启用而设置 `MANUAL_DEMO_LLM_ENABLED=1`；那个开关是通用周期分析，会产生不必要调用并可能争抢资源。

### 14.2 停止

修改 `stop_remote_control_mapping.sh`：

- 先停 WebUI，再停快照写入器和语义侧车；
- 仅当本模式创建了 VLM ownership marker 时调用定向停止脚本；
- 已被其它模式复用的 VLM daemon 保持运行；
- PID/cmdline 继续逐项校验，不使用宽泛 `pkill`；
- 保留会话状态、事件和证据，不删除用户结果。

### 14.3 失败行为

- VLM daemon 启动失败：普通遥控建图继续，target watch 显示 `DEGRADED`，候选可显示但不能确认。
- 检测器失败：沿用当前显式错误，不静默切到另一个后端。
- WebUI 不可用：侧车普通建图继续；没有新 request 时不启用旧目标。
- 目标 request 损坏：忽略并记录错误，保留最后一个已确认生效的 generation；不能崩溃。

## 17. 真机无运动验收

### 17.1 前置安全要求

- 操作者在场，机器狗先由实体遥控器停稳。
- 不授予软件运动控制权。
- 验收命令不得启动自主搜索或 Nav2 行驶。
- 测试前后检查运动相关 topic/action 没有由本功能产生新指令。
- 每轮结束检查并停止本轮所有者进程，不杀复用进程。

### 17.2 阶段 A：基础 smoke

分别执行现有检测后端 smoke，确认新增代码没有破坏普通遥控建图：

```bash
bash scripts/go2w/start_remote_control_mapping.sh \
  --detector yoloe_seg --smoke --no-browser --no-web

bash scripts/go2w/start_remote_control_mapping.sh \
  --detector grounded_sam --smoke --no-browser --no-web
```

要求：检测、mask、`camera_xyz`、JSONL、无回退、无残留进程均正常。

### 17.3 阶段 B：目标监看静止验收

建议给启动器增加显式的无运动验收参数：

```text
--smoke-target "黑椅子"
```

它只能在 `--smoke` 下使用，流程为：解析目标、采一张 D435、检测候选；若有候选则最多发起一次真实 VLM，等待有界时间后退出。无候选应输出 `NO_CANDIDATE` 而不是伪造失败/成功。

在相机前放置已知目标，至少完成：

- 黑色椅子正例；
- 非黑色椅子负例或关系不成立负例；
- 当前可用的史莱姆模拟物/泄漏装置。

检查：

- VLM 只在 detector 候选之后出现；
- 证据图属于同一 frame；
- 结果有 provider、置信度、原因和 latency；
- `camera_xyz` 与 mask 有效；
- smoke 期间没有 SLAM/Nav2/运动指令。

### 17.4 阶段 C：WebUI 静止验收

正式启动遥控建图但保持机器狗静止，在 WebUI：

1. 输入黑椅子并启动监看；
2. 验证解析内容、候选、VLM 和证据图；
3. 在 VLM 在途时立即改为“饮水机旁边的凳子”；
4. 验证旧结果被 stale 丢弃；
5. 清除目标，验证仍继续普通语义建图且不再调用 VLM；
6. 验证自主搜索/网页运动入口仍不可用。

### 17.5 阶段 D：操作者遥控短路线验收

只有 A～C 全部通过后进行。操作者使用实体遥控器低速经过目标区域，软件只观察：

- 目标词每个实时关键帧被调度；
- 无目标路段 VLM 调用数为 0；
- 候选出现后异步复核，建图/SLAM 状态不被阻塞；
- 确认 marker 使用拍摄时刻的 `map_xyz`；
- 同一物体不会在短时间内反复扣费复核；
- 目标关系和锚点在证据图中可见；
- 机器狗全部运动来自实体遥控器。

## 18. 验收判据（Definition of Done）

只有同时满足以下条件，才能宣告完成：

### 18.1 功能

- WebUI 能设置、更新和清除目标。
- 两种 detector 后端都能接收动态目标词和锚点词。
- 黑椅子、关系目标、史莱姆/泄漏类目标至少各有一条完整候选—复核链。
- 没有候选时 VLM 调用数严格为 0。
- 候选出现后才调用 VLM。
- VLM 结论在 WebUI 和事件中可追溯。
- 有可靠坐标时地图能显示确认目标；无坐标时明确降级。

### 18.2 正确性

- detector 候选不能直接变成 `CONFIRMED`。
- VLM 超时/异常不能变成 `REJECTED` 或 `ABSENT`。
- 旧 generation 结果不能写入新目标。
- 关系目标裁剪包含目标与锚点。
- 结果绑定源帧坐标，不使用 VLM 返回时的机器人位姿。
- 普通语义地图的质量门和对象生命周期没有被低阈值候选破坏。

### 18.3 性能与资源

- VLM 最大实际并发为 1。
- 不存在无限 pending queue。
- 不存在每帧调用 VLM。
- VLM 慢请求不阻塞采集线程、ROS spin 和普通语义落图。
- evidence 文件数量有界。
- 不重复加载第二个相同 detector。

### 18.4 安全

- `DISPLAY_ONLY` 运动硬门全部通过。
- 本功能没有任何软件运动指令。
- 不启动 Task Agent/Nav2 搜索。
- 进程停止严格按 PID、cmdline、ownership marker。
- 测试结束无本轮遗留 worker/sidecar/Web/VLM 进程；外部复用进程保持不动。

### 18.5 工程交付

- 相关单元/集成/UI 测试通过。
- Python、Shell、JavaScript 静态检查通过。
- `git diff --check` 通过。
- 操作文档和完整验收报告已生成。
- Grounded-SAM 仍是默认后端，YOLOE-Seg 仍是显式可选后端。
- 自主搜索现有测试无新增回归。

## 20. 回滚方案

该功能必须可独立关闭：

```yaml
target_watch:
  enabled: false
```

关闭后：

- WebUI 隐藏/禁用目标监看卡片并说明配置关闭；
- 语义侧车不读取目标、不注入目标词、不连接 VLM；
- 原有场景检测、危险规则、语义地图和拓扑继续工作；
- Grounded-SAM/YOLOE-Seg 选择行为保持不变；
- 不需要回退或删除任何已有模型。

如运行时目标监看异常，可在 WebUI 清除目标；这只推进 generation 并停止新复核，不停止建图。不得使用关闭整个语义侧车作为日常清除目标的方法。
