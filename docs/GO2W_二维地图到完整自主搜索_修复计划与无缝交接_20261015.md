- `LocalGoalExecutor` 按实际目标距离截断到上限；metric turn_only 保持当前位置；一个 metric intent 不再重复无限发同一个 goal。

6. 健康监视器 `json.dumps(...,allow_nan=False)` 遇非有限诊断数值可能导致节点异常，应确保故障时稳定发布 false/原因，而非崩溃；可以保留数据错误的明确证据并安全编码。
7. 原始传感器重启/时间回退的恢复与地图 epoch 关系仍需明确；不能旧图和新 odom 原点静默混合。
8. 检查是否还有绕过 LocalGoalExecutor/TopologyRouteExecutor 的 metric 目标路径，保证每段目标和规划路径都不超过选定上限。不要仅依赖 UI 数字。

验收：最后代码的针对性联合回归全部通过，故障注入能阻止运动且可解释；Web 的 pose、前沿、语义投影、控制证据都是同一个 map 坐标系。

### P4：启动/停止/保存定位做成实际可用的一套流程

1. 修复第 6 节 PID/归属问题，再验证 `start_nav2_autonomous_search.sh` 重复启动、异常启动、中断、停止及再次启动不会产生重复地图/TF/速度发布者。
2. 一步入口应能明确复用健康的已有上游，或按所有权启动缺失的 wheel/传感器/二维 SLAM；目前 `start_2d_localization.sh` 对缺失 wheel 等会直接报错，尚不是完整冷启动编排。
3. plan-only 必须不产生物理速度。隔离控制验收模式须显式隔离，正常启动不能误复用隔离出口，也不能把隔离通过标成物理执行通过。
4. 修订正常停止流程：取消本会话 Nav2 goal、归零、解除本会话武装；正常结束不应无意锁存急停而导致下一轮搜索永远被仲裁拒绝。真实急停/安全异常仍保持硬停止。
5. 保存地图的 hash/provenance 已实现，但 AMCL 只完成配置模板，尚缺运行闭环：初始位姿来源、生命周期、静止时 amcl_pose 更新/新鲜度、协方差、图授权、审计 mode 等必须补齐。当前 audit 默认 mapping，不能直接声称能验收 localization 模式。
6. 对 saved map 的授权要绑定真实物理验证证据与正确地图；保存成功不授予权限，不能手写空壳证据绕过。优先完成在线 SLAM 搜索，再做可靠的保存/重定位，而非以 AMCL 模板存在宣称完成。

验收：有一条可重跑的正常只读启动命令、一条经授权的运动启动命令、定向停止/恢复路径；保存地图可验证，重启后不会拿旧图/旧 pose 假定位。

### P5：Web 真实只读端到端必须先通过

1. 真实相机、真实 AI、provider nav2，不用 mock 冒充。
2. 至少经历观察、目标选择、真实 ComputePathToPose、正确几何检查及 dry-run 结束，不能再是 NO_LOCALIZATION 或所有目标 TOO_NARROW。
3. `current_pose` 持续有效；长 AI 调用后 nav2 IO 仍新鲜；语义点 frame=map，前沿 frame=map，不得标成 pslam_map 或 source 名。
4. 注入“请求 JSON 擅自 enable motion”必须在只读服务中拒绝；无启动权限时不能触发 arm/NavigateToPose，更不能触急停或误停别人的控制。
5. 明确结束结果：找到/确认目标、主动停止、穷尽、无可达前沿、安全阻塞、预算短测结束，不得统统叫 FINISHED 成功。

验收：归档能证明只读推理和路径链已完整工作；motion_steps=0；物理输出隔离、arm 仍 false，且没有错误物理控制调用。

### P6：新 Nav2 真机短距验收——先取得具体运动窗口

前提：P0–P5 完成且现场观察/急停/清场条件仍成立。用户之后已另行授权新一轮三步、每步 ≤0.2 m，本 AI 当前 0/3；不重复索要同一授权，充电重启后先只读复核，不能刷新步数。

建议提交给用户审核的具体新一轮：最多三条高层动作，前两条 0.10–0.12 m 前进目标，第三条小角度观察转向；每步实测平移不超过 0.20 m。具体角度、扫掠净空和停止余量必须在 P1 有证据后再确定，不能机械套用这个示例。

- 调整验收用到位容差，不能用正常 xy_goal_tolerance=0.20 m 去验一个 0.10 m 请求，导致“尚未动就成功”。验收参数应独立、可审查、可恢复。
- 每步记录地图与 wheel 两种位姿、请求/实测路径和位移、scan/TF/健康、原始/平滑/guarded/碰撞后速度、action 取消及停车时间。
- 限制所有内部重试及纠偏，不能越过用户三步上限。独立监测位移上界，提前留停车余量。
- 失败则停车、保留证据，不自动加第四步。停止/取消、失定位、源断流的物理表现需与隔离结论核对。

验收：新 Nav2 链三步内完成可复核的真实运动与停车；用户限制逐步满足。**短距通过仍不等于 3 m 或大场地整场通过。**

### P7：有对应授权后完成大场地自主搜索验收

1. 分级验证更长目标，最后才实际测试最高 3 m；短距离目标仍应短走。对弯路按路径长度限制，不能只看直线距离。
2. 在大场地实际完成多个地方、多个朝向的前沿探索，找到目标、二次观察确认、停车；期间检查地图漂移/回环、里程计偏差与语义关联。
3. 加入物体靠近停止区、减速区、来源断流、定位失效、人工取消/急停、遥控接管等测试；所有危险输入须停车，恢复须符合既有流程。
4. 验证连续预算：正常使用 max_seconds=0、max_planning_cycles=0、max_motion_steps=0；大量合法步骤后仍正常工作。不能以忙循环替代生产推理负载或大场地实测。
5. “无总超时”不等于无限失败重试；无进展、无可达目标、异常及人工停止都应有明确安全结束。
6. 检查前沿黑名单跨帧有效、不会老绕回同一方向，也不会把失败全部算成穷尽；首次到位后不能重复无限发同一 metric intent。
7. 验证正常结束后第二场搜索可以从 Web 再次启动，旧 goal/旧 epoch/旧武装/旧急停锁存不会影响它。

验收：至少一场完整的大场地真实自主搜索及一场重复搜索成功，3 m 上限与持续预算都由实际日志证明；交付 Web 地址、唯一启动/停止流程、配置说明、地图产物及失败恢复办法。若受场地或授权限制做不到，明确列出未通过项，不写“全部完成”。

### 8.3 现有验证工具及使用条件

- `save_navigation_map.py --verify <map.yaml>`：纯文件校验；`--require-authorized` 应拒绝当前 stationary_map。

## 10. 给接手 AI 的执行要求

请先以最新事实更新本计划的勾选/证据，再按 P0→P7 自主推进。用户需要的是能实际使用的系统，不是额外一轮仅文字评审。对可逆的软件修改、只读诊断、隔离测试、修复和构建应直接完成；无需为常规实现选择反复向用户确认。

仅在真正缺少现场事实、需要超出现有运动窗口或发布最终物理执行权限时询问用户。询问前先完成能独立进行的全部工作，并提交具体可审查的动作、距离、次数与停止条件。不要让用户凭一句“链已恢复”批准一个其实仍被 TOO_NARROW 卡住的系统。

每一项通过都应附实际证据路径和局限。遇到新失败保留原件、说明根因、修复后重跑相应项目；不能把收集错误算注错捕获、把旧版本绿灯算新版本绿灯，或把忙循环当生产负载。
