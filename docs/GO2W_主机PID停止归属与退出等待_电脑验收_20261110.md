# GO2W 主机PID停止归属与退出等待：电脑验收（2026-11-10）

本轮继续用户指定的电脑端工作，处理正式停止/恢复中已记录的通用PID循环缺口。没有连接、部署或启动机器狗，没有调用SDK、云端模型或运动API。原电脑10份PID记录仅只读核对，内容未改；冻结源码05保持原样。

## 复现与修复

原 `stop_all.sh` 从PID文件提取所有数字，未验证当前进程归属，直接向该数字对应的组或进程发送TERM，随后无条件删记录并报告停止。复制脚本到临时项目，三个实际进程反例均失败：无关进程被误停；父进程已退出的自有孤儿组被跳过；拒绝TERM的进程仍存活但记录被删、返回成功。三个用例都只涉及测试自身创建的进程。

新增 `scripts/go2w/stop_owned_host_processes.py`，原全量停止入口改为调用该助手：

- PID记录须为当前用户的普通文件、合法ASCII十进制PID，拒绝符号链接、PID0/1、负数、夹杂文本、多值及超出PID范围的输入；无法验证时保留记录并返回失败。
- 从实际 `/proc` 校验UID、程序位置、PID/start_ticks与进程关系。认可当前项目中的实际执行文件或显式选择的安装目录；ROS包装器须解析到受信任安装中的项目包。命令字符串或普通参数中出现项目路径不算归属证明。
- 拒绝自身及调用者祖先进程。已识别的自有leader可覆盖观测到的子树；独立组中混有无法证明归属的成员时，在发送新信号前拒绝该组。leader已退出时，只有仍可证明归属的同组成员才会被停止。
- 逐PID发送TERM，不向未经验证的整个组广播。可用时使用pidfd；Python3.8缺少pidfd接口时采用发送前PID/start_ticks/UID核对。
- 每份记录默认等待最多8秒；不自动KILL。仅在观测范围内进程全部退出且记录未被替换时移除PID文件。超时、身份变化或替换记录均保留并报错；自有清理已经删除的后续记录不作为失败。
- 主机层失败仍继续尝试原Nav2与二维定位停止入口，但全量停止返回非零，避免停止失败被当作成功。新助手缺失时同样拒绝假报主机停止成功。

三个CANCEL/禁用标志仍为原有提示文件，没有仓库内读取者，不当作取消或制动证明。脚本本身只发主机信号，不直接发送机器人命令，也不接管外部Sport lease。

## 电脑验证

最终 **46项通过，17.30秒，无跳过**：29项新主机PID测试，加原有停止/重置、管理接口和二维停止17项。覆盖正常程序、孤儿、共享组不误停、混合组拒绝、父子树、安装目录匹配/不匹配、ROS资源选择、路径参数伪装、不同项目、坏PID、链接、记录替换、清理时记录消失、助手缺失、调用者保护及发送前身份变化。

pidfd缺失的兼容分支在电脑真实临时进程上强制选用并验证；ROS包装器资源判断使用文件和进程信息夹具，没有运行真实ROS节点。不是Jetson/Python3.8原生运行或真实ROS停栈证明。Shell语法、三个Python文件的3.8语法解析通过，原 `.runtime_venv` 配置及管理模块导入通过；未安装依赖或切换入口。

证据根：`/home/mxt/robotscene_release_stage/acceptance_20261110_host_stop_pc/`。包含旧脚本备份、3项初始失败日志、最终pytest XML与日志、原PC PID记录哈希、候选源码/哈希/归档和 `checkpoint_final.json`。已有停止夹具仅补充复制新助手的依赖，仍只操作临时项目。

## 原生接入边界

此修复以冻结05为父版本，尚未写入05或部署机器狗。下一统一旁路版本必须一起携带停止脚本和助手，不能只替换调用入口。停栈前应加载正确的已验证安装选择；无法确认的原生包装器或孤儿会拒绝停止，不能放宽规则强行通过。

助手对旧数字PID记录的证明来自当前代码路径、受信任安装和观测进程关系，不证明是哪一次启动写下记录。没有提供完整启动身份持久化，也不保证发现已经逃离原关系且未被观测的守护进程；Python3.8核对后再kill的兼容路径不是内核原子身份绑定。记录核对与删除也不宣称抵御任意并发恶意替换。继续保留boot/PID/start_ticks/argv的owned registry和最终remaining检查，不能用本轮通过替代它们。

专用Nav2、Web、映射和其他停止路径未在本轮重新做真实清场审计；真实服务退出、控制取消/制动、原生全TF消费者重建和正式启动/回滚仍待验证。15W完整执行时效、近距回波、D435目标地图坐标和受监督运动仍未完成。机器人供电/boot当前未知，本轮不重新查询，也不切换 `robotscene_current`。
