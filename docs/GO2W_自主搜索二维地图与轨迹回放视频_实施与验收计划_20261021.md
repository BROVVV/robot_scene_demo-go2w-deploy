## 1. 用户要的最终效果

参考图的核心是：地图占画面主体，绿色实际路线在地图上逐步生长，上方有目标和现场照片。无需依赖原聊天图片也能实现，采用以下确定布局：

~~~
┌────────────────────────────────────────────────────────────┐
│ 搜索任务、目标名称/可用的目标图 │ 同步相机画面、当前搜索阶段 │
├────────────────────────────────────────────────────────────┤
│                                                            │
│       逐渐展开的真实二维地图，占主要面积                    │
│       绿色实际轨迹 + 带朝向的机器人箭头                    │
│       起点、导航到位、疑似目标、确认目标、终点              │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ 已用时间 · 累计行程 · 播放倍速 · 地图/定位数据状态           │
└────────────────────────────────────────────────────────────┘
~~~

默认输出 1920×1080、30fps、H.264 MP4（yuv420p、faststart），另存封面 JPEG 和最终地图 PNG。无需音乐。中文应正常显示，不能方框乱码。

具体呈现：

1. 未知区域浅灰、已知自由区域白、占用区域深灰；图例区分三者。
2. 地图按历史时间逐渐出现，不能从第一帧就显示完整最终地图冒充建图过程。
3. 实际位姿估计轨迹为绿色实线，当前机器人用带朝向的箭头，起终点清楚标记。
4. 如显示规划路径，只能使用不同颜色的虚线并标“规划”，不得算作实际行程。第一版可以不显示规划路径。
5. 顶部目标图只在输入或实际检测提供有效图像时显示；否则用任务名称，不要求用户上传图片，不生成假的目标照片。
6. 显示相机画面及真实关键事件。只有实际确认事件才能显示“找到目标”；疑似目标、人工停止、失败、超时、未找到等分别显示。
7. 结尾停留 3 秒，展示完整记录范围的地图、分段轨迹、结果、时长、有效累计行程。
8. 默认探索过程 10 倍速；首次实际移动、目标确认和停止等关键片段默认正常速度。支持 1×/5×/10×/20×重新生成；事件重叠合并，避免重复片段。
9. 不限定整场搜索总时间或步数。超长会话必要时自动分章，同时提供总览/播放列表，不能影响搜索本身。

第一版必须完整实现上述地图、轨迹、相机、事件、自动生成和 Web 播放下载；参考图里的透视照片贴地、三维场景纹理拼接和配乐不属于本次必做范围。

## 3. 实现架构与模块归属

采用“独立只读采集进程 + 持久任务队列 + 离线渲染器 + 现有 Web”的结构。

建议新增模块（路径可微调，职责不得混淆）：

~~~
app/search_replay/
  models.py                 版本化数据合同、状态和质量标记
  manager.py                会话绑定、采集生命周期与任务调度
  storage.py                原子写入、文件索引、校验、保留策略
  timeline.py               时间对齐、倍速和关键片段时间映射
  trajectory.py             坐标处理、分段与有效行程统计
  renderer.py               地图/轨迹/相机/中文标注绘制
  encoder.py                FFmpeg 启动、失败处理与成品校验

scripts/go2w/record_search_replay_ros.py
scripts/go2w/render_search_replay.py
configs/go2w/search_replay.yaml
~~~

约束：

- ROS 采集器只订阅地图、TF、定位和里程计；不创建运动客户端，不发布 cmd_vel，不发导航目标，不启动第二套建图。
- 每个真实活跃搜索会话最多一份采集器。新会话和旧会话有独立 session_id、录制 UUID、目录和控制通道。
- Web 管理器使用后台线程/进程处理采集启动、控制消息与磁盘工作。搜索事件回调和服务锁内只允许有界入队，不进行读图、压缩、编码、网络请求或等待子进程。
- 建议每会话启动独立 ROS 子进程，通过小 JSON 控制消息及就绪/完成状态通信；图像和地图走磁盘，不把大数据塞入 stdout 或事件总线。
- 采集器启动要在搜索 executor 真正工作前发起。启动就绪等待只能在后台进行且有界（默认最多 2 秒）；超时不阻止搜索，准确标注未录到的起始区间。
- 采集不能依赖浏览器保持连接，关闭页面后也继续记录。
- 录制/编码失败只影响回放状态，不能改写搜索结果、导航就绪、停车、急停或运动许可。
- 编码默认在搜索结束后执行；全局最多一个编码任务。新搜索开始时降低编码优先级或在可恢复分段边界暂停，不抢占导航和 AI 资源。
- 任务持久化并具备单实例文件锁；Web 重启后扫描、恢复未完成任务，不能重复编码或错误接管别的进程。

## 4. 数据合同与真实性

### 4.1 每个会话的文件结构

在现有会话目录下增加独立 replay 子目录，不改变原事件、图和状态文件语义：

~~~
outputs/live_runs/<session_id>/
  ...现有会话文件...
  replay/
    manifest.json
    capture_status.json
    job.json
    timeline.jsonl
    poses.jsonl
    frames.jsonl
    events.jsonl
    maps/
      <content_hash>.npz
    frames/
      <frame_seq>.jpg
    artifacts/
      replay.mp4
      final_map.png
      cover.jpg
      chapters.json          仅超长会话需要
    render.log
~~~

manifest 至少包含：schema_version、session_id、recording_id、任务/目标、backend、真实或合成数据来源、起止时间、坐标段列表、采样配置、有效数据范围、gap/drop 计数、文件索引/哈希、搜索结果、回放生成状态和质量说明。

- 原始记录 append-only；新版本产物不能无提示覆盖旧证据。
- JSON 禁止 NaN/Infinity；损坏末行可恢复，坏行须计数，不能把其他会话接上。
- job.json 与最终文件采用临时文件+原子重命名；未完成 MP4 不能标成 READY。
- 会话元数据中只保存轻量回放状态/URL，不内嵌完整轨迹、地图或 base64 图片。

### 4.2 地图

直接读取 /map 的 OccupancyGrid，保留 stamp、frame_id、分辨率、宽高、完整 origin 位姿和原始栅格。

- 内容 hash 必须覆盖完整栅格及 frame/尺寸/分辨率/origin；相同内容重发只追加轻量时间引用，不重复存整图。
- 默认变化图最多每秒落盘 1 次；首图、末图、关键事件图优先保留。高频中间图可合并，但必须记录实际丢弃/合并数量。
- 不修改输入地图，不把未知当白色，不通过膨胀/腐蚀“美化”真实障碍。
- 地图扩展、原点变化、负坐标和 origin yaw 必须正确处理；不得按数组下标直接叠轨迹。
- 无地图时输出“本段地图不可用”，不能偷偷拿上一会话的最终地图。
- 开始时已有地图允许展示，但须标注“本次起始已有地图”，不能称为本次新探索成果。

### 4.3 位姿、轨迹、回环与行程

- 默认约 10Hz 记录 map→base_link 和定位有效性，保留与记录时刻对应的 TF 时间证据；不要无视时间查 latest 后伪装为相机采集时刻。
- 同时记录 /go2w/odom/fused 轮式里程及必要的 map→odom_fused 证据。
- 位姿必须有限、坐标一致、定位有效且新鲜；无效期间中断轨迹，不补一条直线跨过数据空洞。
- 机器人重启、地图重置、坐标系改变、时钟回退、采集进程重启或明显定位跳变均产生新段。
- 区分“同一坐标系中的地图尺寸扩展”与“新的坐标周期”；不能每张 map 更新都当重置，也不能所有 frame_id=map 都当同一个周期。
- 轨迹是实测位姿估计，不是地面真值。不得从发过的指令、规划路线或 VLM 描述推造机器人位置。
- 累计行程使用同段、有效、连续的轮式里程增量；定位跳变、重启跳变不计为移动。另保留净位移，不能混淆两者。静止抖动处理需有明确规则和误差说明。

**回环处理的最低交付合同：**

第一版交付“按当时地图/定位回放”的真实时间序列；识别明显 map→odom 修正，分段并标“定位调整”，不画跨段连线。最终总览可叠加同坐标周期的历史估计轨迹，但必须标注“历史定位轨迹，未统一回环优化”；不能将有坐标冲突的段硬贴到最终地图。

如果仓库可可靠提供优化后的 SLAM 关键帧及关联里程，可以追加“最终优化轨迹”：用关键帧锚定和相对里程重投影，并用回环测试验证。拿最终一条 map→odom 变换套全部历史位置不算正确实现。优化能力缺失时仍须完成第一版，明确标记，不能声称轨迹已经全部回环校正。

### 4.4 相机与关键图片

- 优先复用现有相机来源和时间换算，默认最多 5fps 保存颜色帧，不为录像另开第二套相机设备/ROS 发布者。
- 对 immutable RGB-D 帧只取颜色与元数据，不额外下载深度。若使用现有 MJPEG/最新帧，记录接收时间质量，不能假称硬件曝光时间。
- 会话要拥有实际图片副本或可靠的持久链接，不能只保存会被缓存清理的临时路径。
- latest.jpg 与 status 不是天然原子的一对。读取要验证一致性或使用原子帧来源，损坏 JPEG 重试/跳过并计数。
- 网络访问绕过本地机器人相机的 HTTP 代理；保留有限请求超时，不能卡住停止。
- 目标发现/确认等关键事件保留附近真实帧；没有匹配图片显示文字，不补造图片。

### 4.5 时间轴

每条采样记录至少有：session_id、recording_id、segment_id、seq、源时间（如有）、本机接收 monotonic 时间、本机 Unix 时间、时间质量。

- 同一主机 monotonic 时间负责持续时间和排序；跨机器源时间使用已验证的换算或标为接收时间。
- 时间回退分段；不可把机器人重启后的 stamp 接到上一次时间轴。
- 地图、相机、轨迹、事件共享同一回放时钟，倍速仅改变展示映射，不改原始记录。
- 默认用当前播放时刻之前、最近的有效相机帧，超过 1 秒无新帧则标注“图像中断”；不能拿未来图像填过去。
- 地图长时间未变可复用同内容，但必须区分“图内容没变”和“地图源已断流”。
- 关键片段映射、结尾停留、暂停区间和原始搜索时间都要可追溯。

## 5. 生命周期与异常处理

回放状态与搜索状态独立：

DISABLED / STARTING / RECORDING / FINALIZING / QUEUED / RENDERING / READY / PARTIAL / FAILED。

READY 表示完整预期记录范围的成品已校验；PARTIAL 可以有可播放 MP4，但存在缺段/资源降级/数据缺失，必须显示原因；FAILED 不能假装有成品。

生命周期必须覆盖：

1. 搜索会话创建：绑定目录，记录开始边界，启动采集；不能绑到“当前最新 session”的可变全局变量。
2. 搜索运行：非阻塞采样；采集器异常须在界面/归档中标注。
3. 任意终态：找到、未找到、人工停止、预算结束、异常退出均触发一次幂等收尾。
4. 停车与解除武装优先，不能等待录像 flush/编码；终态仅排入收尾任务。可保留最多 2 秒停车画面作为尾段，明确事件时间与录制结束时间的区别。
5. 停止与终态重复、旧 worker 迟到事件、连续启动新会话，都不得串片。
6. Web/worker 崩溃：采集器发现控制通道 EOF 后收尾或停止；记录中断。下次启动根据 manifest/job/文件锁恢复，不重新假造活跃搜索，也不偷偷恢复运动。
7. 编码器失败、磁盘不足、无图、无相机、无定位、用户从未移动，均有清楚结果，不影响搜索的控制与安全路径。

开始前被拒绝、没有真正创建会话的请求，不生成虚假的搜索视频；有会话但启动失败则保留失败记录，可生成带失败说明的短回放。

## 6. 渲染、编码与性能

### 6.1 渲染

- 用离线绘图/图像合成，优先复用 NumPy、OpenCV 和可用的 Pillow/中文字体；不是浏览器录屏。
- 对每个坐标段采用该段完整已录数据的固定世界视窗，第一帧仍只画当时已有地图；避免地图变大时不停缩放抖动。
- 维持米制比例，不拉伸地图；保留比例尺、坐标方向和图例。
- 正确处理图像 y 轴向下与地图 y 轴向上的转换，机器人 yaw 不得镜像。
- 最终地图视窗包含该段所有有效地图范围和轨迹，并留合理边距。
- 只有真实地图自由区域和有效位姿覆盖时才显示相应内容。缺数据的区域/时段明确标记。
- 地图主体至少占画面高度约 65%；中文字清晰、相机不变形、长任务名合理折行。
- 不因滤波、插值或曲线平滑把停顿、折返、小回退或路径跨墙“画漂亮”。

### 6.2 编码

- FFmpeg 用参数数组启动，不使用 shell 拼接用户任务文字、路径或会话 ID。
- 默认 H.264/yuv420p/faststart，30fps，编码线程默认 2；核对当前编码器实际支持。
- 字体从明确可用的 CJK 字体选择，缺失时由实现 AI 补齐并验证，不让用户手工调中文字体。
- 编码临时输出如 replay.partial.mp4，成功后 ffprobe 检查视频流、尺寸、帧率、时长，抽取首/中/尾帧检查，再原子发布 replay.mp4。
- 不在内存一次性生成全部帧；流式或分块编码。子进程异常要关闭管道、回收进程、保存 stderr。
- 目标完成标准不是“有个非零字节 MP4”，而是实际可解码、可拖动和内容正确。
- 相同录制及相同渲染配置有稳定指纹；重复任务可复用成品，重新生成不能启动无限并发。

### 6.3 有限资源与无限搜索兼容

建议默认：单会话原始素材软预算 8GiB，全局回放素材软预算 30GiB，最小剩余磁盘保护 2GiB；均可配置。接手 AI 根据本机空间复核，最终记录生效配置。

- 不给自主搜索增加总时长/步数上限。
- 避免相同地图、相同相机帧重复落盘；压缩地图，使用有界队列。
- 压力增大时先降低普通相机采样率，再合并普通地图中间帧，保留关键事件、有效轨迹和质量信息。
- 丢帧/降级必须在 manifest 和界面可见；达到硬资源限制时停止相应录制并标 PARTIAL，不能占满磁盘或停止机器狗。
- 若长会话分章，所有章节覆盖范围、倍速、缺段和总览必须有索引；不能只导出最后几分钟却标“完整视频”。
- 在正常空闲负载及当前应用工作负载下分别测录制开销；忙循环不是生产负载验证。不要承诺未经测试的 CPU、内存或生成耗时数字。

## 7. Web 接口与保留策略

建议在现有路由增加：

| 接口 | 行为 |
|---|---|
| GET /api/search/history/{session_id}/replay | 状态、质量、进度、成品 URL、时长、分辨率、失败/缺段说明 |

| POST /api/search/history/{session_id}/replay/render | 重试或按允许倍速重新生成，只提交后台任务 |

接口名称可统一调整，但不能把视频二进制塞进原 state/history JSON。不得暴露任意文件下载、绝对文件路径或 shell 命令。

- 复用现有访问限制；严格校验 session_id 与 resolve 后的文件归属，防止 ../、URL编码绕过及符号链接逃逸。
- 存在会话但无回放与会话不存在分开表达，尚未生成视频不返回伪 MP4。
- 前端在当前会话结束区和历史详情中显示“录制中/生成中/可播放/部分记录/生成失败”；READY/PARTIAL 成品可内联播放和下载。
- 重新生成只影响回放，不再次启动搜索、AI 推理或机器人运动。
- 页面刷新、断开、重连不触发重复录制/生成。切换历史会话不覆盖当前搜索状态，播放器资源正确释放。
- UI 只展示对用户有用的状态和原因，不把 ROS topic、manifest schema、PID 等实现细节堆进产品页面。

**历史清理必须实改，不能只写文档：**

当前 _prune_locked 会删整个旧会话。加入回放后必须通过归档/回放共同的保留合同避免删掉 RECORDING/FINALIZING/QUEUED/RENDERING、播放器/下载正在使用或显式保留的会话。

默认可沿用最近 10 个已结束会话数量策略，但应独立处理素材预算；优先删除可重建的非关键原始素材，必须明确哪些成品因此仍可播放但不可重新生成。删除会话时更新回放索引，不留失效下载入口。不得为本功能对已有用户记录进行一次性批量删除。

| 项目 | 必须看到的证据 |
