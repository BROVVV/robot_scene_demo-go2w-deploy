## 搜索生命周期压力路径修复

暂停/停止验收不能只看 HTTP 接收成功。首个测试仅等 1 秒便要求协作暂停完成，判据过早，保留失败记录；后续真正等待事件时又发现三个实际问题：

1. worker 的启动心跳无条件报告 `running`，尚未创建 explorer 时，Web 已允许暂停；worker 原先直接丢掉此时的暂停/停止命令。现在心跳保留真实启动阶段，在首个 explorer 事件处才进入 running；暂停/停止意图在加锁状态中保留，首个 explorer 事件应用一次。停止后不能由 resume 覆盖，下一会话清空旧 holder 和控制意图。
2. worker 终态回收关闭 stdin 与 Web 停止请求并发时，`_send()` 的 `write/flush` 可能抛 `ValueError: I/O operation on closed file`，引起 HTTP 500。现在在 I/O 边界处理关闭管道；JSON 序列化仍在异常处理外，非法命令数据错误不被吞掉。
3. 取消和干跑路径原有三处 Python 3.9 字典合并运算符，在机器狗 Python 3.8 上报 `unsupported operand type(s) for |: 'dict' and 'dict'`。三处改为字典展开，合并顺序保留。对 app/主要脚本的 AST 检查中，其余运行时 `|` 为集合或位运算，没有据此误改类型注解。

电脑与机器狗各 131 项搜索控制、图事件、worker 解释器、Nav2 后端、会话恢复回归通过。另用机器狗 Python 3.8 实际子进程 JSONL 协议做明确的 **mock 后端软件探针**：启动后立即发 stop，返回 `OPERATOR_STOP`、观测事件为 0。该结果只证明早停协议，不是硬件/导航验收。

正式只规划入口重启曾在启动审计中因 `scan_fresh` / `mapping_scan_fresh` 拒绝，编译后台负载仍在；保留失败日志，没有直接调用下层 Web 入口绕开审计。负载结束后需再次走正式入口并重跑真实暂停/恢复/停止。
